# Motion

## Principles

A new animation answers to these before it picks a curve. This is a windowed desktop app driven by a pointer and the keyboard — there are no swipes to ride, so the principles land on drags, folds, swaps and key repeats.

- **Every animation is interruptible, because the input that interrupts it is the normal one.** Panes get toggled faster than they fold, tabs switch mid-cross-fade, a drawer is reopened while it is still leaving. The replacement inherits the velocity of what it cut off (motion, never CSS transitions), and no state may be correct only once an animation has finished — an animation is how a change looks, never when it takes effect.
- **A drag moves its surface from the first pixel.** Pane separators, column resize, the `EditableList` grip, reorderable strips, swipe-dismiss: each follows the pointer directly, animates nothing while the pointer is down, and stops any fold it interrupts. A threshold decides the *outcome*, never whether the surface has started answering.
- **Where a change commits is a function of what it costs.** Reversible, purely visual outcomes resolve live, so backing out is dragging back (a pane collapses as the pointer crosses the threshold and reopens if it crosses back; Escape restores the size the drag started from). Anything that persists or runs commits once on release, never per frame.
- **Motion states where a surface lives.** A surface enters from its own edge and leaves the same way — drawers from the right, a pane out of its seam, a popup from its anchor. A fade in place gives the user a surface with no address; an arrival from somewhere it does not live sends them looking in the wrong place next time. That is why a list collapsing is its rows sliding to their new `y`, not rows fading where they stand.
- **Frequency is the animation budget, and the keyboard sets the ceiling.** Anything a held key repeats gets no animation at all; anything opened dozens of times an hour stays at popup weight (150 in, 100 out); a longer curve is affordable only where the moment is rare and page-sized. A flourish met twenty times an hour is friction, and on a list it is smear.

## Recipes

- `motion` library for interruptible animation, not CSS transitions (transitions snap under frame drops). Exception: pure colour/opacity hovers.
- House curve `[0.32, 0.72, 0, 1]`, 150–300ms. Collapse via width/transform; no whole-panel opacity fades. `AnimatePresence` for mount/exit of conditional chrome. No layout shifts on hover — reserve space, animate opacity/transform only.
- **A `transition-[…]` list must name every property the element's own state variants change.** A surface hovering both its ring and its fill but listing only `box-shadow` reads as two durations on one control. Rings and shadows are `box-shadow`; `transition-colors` never covers them. Siblings lighting up on the same pointer event share one duration.
- **Anything keyed to the highlighted row of a keyboard list has no transition** — the highlight jumps a row per keystroke and a fade smears indicators down the list. Hover-only reveals inside one row may still fade.
- **Definition rows do not animate at all.** Schema picks, searches and filters replace the whole row set, so per-row enter/exit leaves old rows holding their place while new ones mount below — the table doubles its height and snaps back. Row-level `AnimatePresence` is for rows arriving in a list that stays the same list; the only animation there is the skeleton→content swap around it, whose exit runs at `duration: 0` so `mode="wait"` does not hold an empty pane.
- **Virtualized reorder** (navigator tables): motion `layout` cannot work with tanstack-virtual — stable `getItemKey` + `motion.li` `initial={false} animate={{ y: virtualRow.start }}`. Rows sliding to a new `y` *is* the collapse animation; `{ duration: 0 }` while search filters, since churn per keystroke reads as noise.
- **Swapping two panels in one slot**: `AnimatePresence mode="popLayout"`, opacity + small `x` offset in the push direction, 150–180ms.
- **Collapse/disclosure**: animate CSS grid rows (`gridTemplateRows` `0fr` ↔ `1fr`) around a `min-h-0 overflow-hidden` child.
- **A conditionally rendered note animates in and out** — `AnimatePresence initial={false}` around `MotionCollapse` (`collapse.motion.tsx`), keyed per condition so two exclusive notes cross over instead of jumping. An alert popping into a form the user is filling reads as a layout glitch. **The stack's gap animates with it**: a collapsed item is still a flex item, so `MotionCollapse` folds the parent's `rowGap` into its own clipped height — grid parents (the kit's dialogs) ignore item margins and keep the snap.
- **Popup enter/exit** (all kit menu/popover/select content): `animate-in/out` + fade/zoom/slide, `data-open:duration-150 data-closed:duration-100` on the house curve — the shipped defaults read as no animation. Exits stay shorter than entries.
- **Tab content swap** cross-fades in `$tabId.tsx`, never around the layout route's `<Outlet />` (an exiting presence child keeps rendering while `Outlet` resolves to the current match, so a tab cross-fades with itself). Keyed on resource id + `tab.id` — a tab id repeats across resources, so keying on it alone keeps one resource's state and placeholder rows alive under the next. Each tab takes its identity as props so the frozen exiting element stays valid. Two tabs are mounted for the overlap and the exiting one still owns whatever it registered globally, so **every `document`-scoped hotkey a tab registers passes `conflictBehavior: 'replace'`**. Element-scoped hotkeys never collide.
- **Reorderable strips**: `Reorder.Group`, `layout="position"`, animate layout only while dragging — no drift when labels change width. Value identity rules in [gotchas.md](gotchas.md).
- Scroll-edge cues never use JS scroll listeners — `scroll-fade` (CSS mask) for plain scrollers, `table-fade` for the data table ([gotchas.md](gotchas.md)).
- **Refetching values pulse; only first load gets a skeleton.** A displayed number whose query is refetching keeps its value and dims + `animate-pulse` — gate on `isFetching`, since `isLoading` is first-load-only and a refetch would show stale data with no cue.
- **`DitherBackground` is a bare shader; pages own its entrance.** It compiles and starts a continuous render loop on mount, which competes with entrance animations — a page that animates in mounts it after its own entrance.

## Pane folds

`motion-panels` (`monorepo.md`) animates a sized pane's own width/height on the house curve whenever its target changes; the fill pane is plain flex, so one clock moves both. What the app has to get right:

- **Content rides the fold, never a second clock.** A pane forwards motion's presence props to its content block, so a pane fades, slides or scales its contents while the package animates its size; the pane's `transition` prop is the one knob for both. **`initial` doubles as the closed state** — supply `exit` only to leave differently than you arrived, and note that either one hands presence the decision of when the content unmounts.
- The package anchors the content block to the pane's **still edge**, so pivot a `scale` there (`origin-left` before the fill pane, `origin-right` after it) and never add a compensating `translate` — the content does not ride the seam. Never animate the content's own width or height: the package owns them.
- **Content stays mounted** by default once opened, clipped at zero while collapsed, because a remount costs the whole mount before the first animated frame and reads as a click that did nothing (the chat's message list is ~300ms of markdown against a 250ms fold). Keeping is lazy, and a pane already open on first render skips its entrance. Pass `keepMounted={false}` where mounting is cheap and keeping is not — a kept pane's work keeps running while it is closed.
- **Only pin content that bleeds to its own edges.** Pinning (`pin`) lets a Monaco editor or virtualized table lay out once per fold instead of once per frame, but a card with a border, rounded corners or a shadow puts a visible edge at the pinned width — which is why the app's panes, all cards, do not pin.
- Drags never animate: every pointer move jumps the pane and its content to the pointer and stops any running fold; the size commits on release. Under `prefers-reduced-motion` every fold drops to `{ duration: 0 }`.
- Runner results and logger detail are plain `div`s flipping an inline size with no animation.
