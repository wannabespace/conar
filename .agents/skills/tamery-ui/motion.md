# Motion

- `motion` library for interruptible animation, not CSS transitions (transitions snap under frame drops). Exception: pure color/opacity hovers — `transition-colors` fine.
- House curve `[0.32, 0.72, 0, 1]`, 150–300ms. Collapse via width/transform; no whole-panel opacity fades. `AnimatePresence` for mount/exit of conditional chrome. No layout shifts on hover — reserve space, animate opacity/transform only.
- **Anything keyed to the highlighted row of a keyboard list has no transition** — highlight jumps a row per keystroke; a fade smears indicators down the list. Hover-only reveals inside one row may still fade.
- **Virtualized reorder** (tables tree): motion `layout` can't work with tanstack-virtual — stable `getItemKey` + `motion.li` `initial={false} animate={{ y: virtualRow.start }}`. Rows sliding to new `y` *is* the collapse animation; tween `{ duration: 0 }` while search filters (churn per keystroke reads as noise). Ref: `navigator/tables-list.tsx`.
- **Pane folds** (`motion-panels`): a sized pane animates its own width/height with motion's `animate(motionValue, …)` on the house curve (250ms, the package's one `TRANSITION`) whenever its target changes — open, close, or a new `size` from keyboard or double-click. The fill pane is plain flex, so it grows or shrinks in the same frames; one animation, one clock. Its content can opt out of reflowing with it (`pin` on the filling pane, off by default and off in the app): while any sized pane in the group is folding, the group pins the fill pane's content to its final size (the group's size minus every sized pane's target, measured once at fold start) and clips it, so a Monaco editor or a virtualised table lays out once per fold instead of once per frame — the content is sized once at the start and anchored to the edge away from the folding pane (the one that does not move), so it holds still while the pane edge slides across it, VS Code style — anchoring it the other way would drag the content along with the moving edge. Drags stay live: the pin lifts the moment a drag starts, so the content follows the pointer. **Only pin content that bleeds to its own edges.** A card with a border, rounded corners or a shadow puts a visible edge at the pinned width, and the fold either clips that edge off until the last frame or leaves it standing 260px inside an empty pane — which is why the app's panes, all cards, do not pin. The content never rewraps through an open or close: it holds the pane's resting pixel size, anchored to the edge facing the fill pane (`justify-content` inline on the pane), so the moving edge carries it out and in — no transform, nothing to drift. A resize (keyboard, double-click) animates the content's size in step with the pane instead, so it reflows with the pane rather than snapping to the new width behind a moving clip edge — and always on the package's house curve: the pane's `transition` prop belongs to the toggle (a fold from or to zero), so a 10px arrow step never rides the open/close spring. The pane clips only while collapsed, dragging or animating, so card shadows survive at rest. Drags never animate: every pointer move jumps the pane and its content to the pointer (which also stops any running fold), a drag past the collapse threshold snaps closed, and the size commits through `onSizeChange` on release, never per frame. Content stays mounted while animating and unmounts once closed. Runner results and logger detail are plain `div`s flipping an inline size with no animation. Under `prefers-reduced-motion: reduce` the package drops every fold to `{ duration: 0 }`, so panes jump instead of gliding.
- **Custom pane animations** ride on the fold, never on a second clock. A pane forwards motion's presence props (`initial`, `animate`, `exit`, `variants`) to its content block, so a pane fades, slides or scales its contents with the same API as any `motion.div` while the package animates the pane's size — the pane's `transition` prop is one knob for the whole fold and drives the size and the content alike, and a transition inside a target still wins over it (`animate={{ opacity: 1, transition: { delay: 0.1 } }}`). **`initial` doubles as the closed state**, so a pane leaves the way it arrives and every open starts from the point it was given — supply `exit` only to leave differently than you arrived. Either one hands presence the decision of when the content leaves, so it unmounts when that animation ends, which can be before the pane finishes closing; with neither, the content outlives the fold so the pane never shrinks around nothing. A pane **keeps its content mounted** by default once it has been open, clipped at zero while collapsed, and the fold animates that content between `initial` (or `exit`) and `animate` rather than exiting it: a remount costs the whole mount before the first animated frame, which reads as a click that did nothing — the chat's message list costs ~300ms to mount (markdown per message, measured with React's Profiler) against a 250ms fold. Keeping is lazy, so a pane closed at boot still mounts nothing until it is first opened, and a pane already open on first render skips its entrance — a page load does not slide its panes in. Pass `keepMounted={false}` for content that is cheap to mount and expensive to keep, and note that a kept pane's work keeps running while it is closed (the chat's stream included). A pane's `className` and `style` land on that content block, not on the pane's own box, and the package anchors that block to the pane's **still edge** — the one away from the fill pane — so the content holds its place while the seam sweeps across it. Pivot a `scale` on that same still edge (`origin-left` for a pane before the fill, `origin-right` for one after it) and never add a `translate` to compensate for drift: the content does not ride the seam, so a compensating translate doubles up and throws the content the wrong way. The pivot is the caller's call, the package holds no origin table. Never animate the content's own width or height — the package pins those for the fold and its inline size wins over a `style` width/height. `custom` reaches both the content and its presence, so dynamic exit variants work.
- **An under-damped spring undershoots past its target**, and a pane closing to `0` therefore asks for a negative size: `width: -52px` is an invalid declaration the browser drops (measured: motion's default `{ type: 'spring' }` reaches -52 on a 320px close). The pane renders `abs(value)`, so the undershoot becomes a **rebound off the closed stop** — the pane bounces open by the undershoot and settles, the neighbour keeps moving instead of freezing at the group edge, and nothing leaves the group. Not `max(0, value)`: that freezes the pane at zero for the whole undershoot and then pops it open a few px on the way back; not a negative margin on the pane: that grows the neighbour past the group into the gutter.
- **A fold must survive being interrupted**, because panes get toggled faster than they animate. Three things twitch if they are done the obvious way: pinning the content to the pane's *live* size (interrupt a half-open pane and it pins the size it happened to reach, so the content jumps before sliding); pinning imperatively after mount (re-opening right after a close remounts the content unpinned for one frame); and pinning only *while folding*, which silently breaks every close — an exiting child renders from the frame before its removal, a frame in which nothing knows a fold began, so the content shrinks with the pane instead of sliding out, while opens look perfect because they mount fresh. All three go away by keeping the content's size in a motion value the fold owns — untouched on a close, jumped to the target on an open, animated alongside the pane on a resize — because a motion value keeps moving after presence freezes the exiting child's props; and depending on the `transition` prop's identity in the animation effect (an inline object is new every render, so any unrelated re-render restarts the fold) — the fold reads it through `useEffectEvent`. The interrupted animation is left to motion, which carries velocity into the replacement — but motion's `stop()` ticks the old animation once more at the current time first, and if its duration has already elapsed (a skipped final frame, any jank) that tick *finishes* it and fires its `onComplete` after the new fold has already set the folding state, so the folding state is cleared from the value's own `animationComplete` event, and only when the value sits at the current target — a stale finish lands at the old target, before the new fold's first frame; otherwise a pane without `exit` unmounts its content mid-fold and shrinks around nothing, and one with `exit` slides its content out unclipped. The content also stays mounted for as long as a drag is live: a drag past the collapse threshold collapses the pane mid-gesture, and the grip being dragged sits inside that content, so it has to survive until release.
- **Collapse/disclosure**: animate CSS grid rows — `animate={{ gridTemplateRows: open ? '1fr' : '0fr' }}` wrapping a `min-h-0 overflow-hidden` child.
- **Swapping two panels in one slot**: `AnimatePresence mode="popLayout"`, opacity + small `x` offset in the push direction, 150–180ms.
- **Tab content swap** cross-fades in `$tabId.tsx`, not around the layout route's `<Outlet />`: an exiting `AnimatePresence` child keeps rendering, and `Outlet` resolves to the *current* match, so it would cross-fade the incoming tab with itself. Keyed on `tab.id`, each tab component takes its identity as props (schema/table, tabId, section) and reads only the `$resourceId` context, so the frozen exiting element stays valid. Two tabs are mounted for the 150ms overlap — two table grids at once.
- **Reorderable strips**: `Reorder.Group`, `layout="position"`, animate layout only while dragging (snap otherwise — no drift when labels change width). Value identity rules in [gotchas.md](gotchas.md).
- Scroll-edge cues: never JS scroll listeners — `scroll-fade` (CSS mask) for plain scrollers, `table-fade` overlay for the data table (mask would clip the scrollbar; [gotchas.md](gotchas.md)).
- **Popup enter/exit** (all kit menu/popover/select content): tw-animate-css `animate-in/out` + fade/zoom/slide, `data-open:duration-150 data-closed:duration-100` on the house curve — the shipped defaults read as no animation. Exits stay shorter than entries.
- **`DitherBackground` is a bare shader; pages own its entrance.** The paper-design `Dithering` shader compiles and starts a continuous render loop on mount, which competes with entrance animations — a page that animates in mounts it after its own entrance (`auth.tsx`: 700ms timer, then a 1.2s opacity fade on a wrapper). Static pages render it bare.
- **Refetching values pulse; only first load gets a skeleton.** A displayed number/label whose query is refetching keeps its value and dims + `animate-pulse` (gate on the query's `isFetching`, not `isLoading` — `isLoading` is first-load-only, so a refetch shows stale data with no cue). Ref: table toolbar row count (`table/-components/toolbar/toolbar.tsx`).
