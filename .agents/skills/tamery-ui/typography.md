# Typography, density & radius

- Fonts: Geist / Geist Mono (fontsource variable, globals.css). Monaco's `fontFamily` in `monaco.tsx` must name the same family as `--font-mono`.
- `text-sm` primary labels (rows, tabs, popup rows) · `text-xs` secondary/chips/menu group labels · `text-2xs` micro labels; section headers add `font-semibold tracking-wider uppercase text-muted-foreground`
- Row heights: menu/list rows `h-7`, connection-list rows `h-9` (icon `size-5`, color bar `h-4`), tab bar and pane headers `h-8`, toolbars `h-11`–`h-12`, chips `h-5` (filter) / `h-6`. Data-table header has **no fixed height** — padding + line heights land on 32/44px naturally; `--table-header-height` in globals must match, and hairlines stay non-layout (`inset-ring`) — a real `border` adds pixels.
- Kit `TableHead` is `h-8 text-xs text-muted-foreground` (macOS list header, not the registry's `h-10 text-foreground`).
- Kit `Table` takes `size` for row density: `sm` is the app's dense list tier (`text-xs`, `h-9` body rows, `px-3` on every `th`/`td`), `default` the registry's roomier one. A page that wants dense rows passes the prop — re-dialing `td`/`th` padding, row height or font size from a call site is the missing-prop smell rule 11 names. Header rows never hover (the kit scopes `hover:bg-accent` away from `thead`), so no call site turns it off.
- **Three weights, by role.** Body `400` for controls — `Button`, `Toggle`, `ButtonGroup` and `InputGroupAddon` carry no `font-medium`, so a control label sits at the same weight as the text it acts on and never outshouts the values around it. `font-[450]` is the **floating-row** weight, a half-step the variable face gives for free: menu, command, select and context-menu items and tab-bar tabs take it, so rows on a popup surface read a touch firmer than prose. Rows on a page surface — navigator tables, definitions, action rows — stay at body weight, and a selected row is marked by its fill (`data-active:bg-primary`) alone: a weight bump on top of a filled row is a second signal for one state, and it reflows the label the instant it is clicked. `font-medium` is for type roles, not chrome: titles and headings (`font-heading` + `font-medium`), `Label`/field legends, and chips that have to read at `text-xs` (`Badge`, `Kbd`, combobox chips, `TableHead`) keep theirs. A call site adding `font-medium` to a button is re-dialing the kit.
- `tabular-nums` for counts; `font-mono` for values/hosts/SQL
- Radius scales with size (kit encodes — don't override): `h-8`+ controls `rounded-xl`; `h-7` `rounded-lg`; `h-6` chips/badges/kbd/checkboxes and menu/select/command items `rounded-md`–`rounded-lg`. `Button`, `Select`, `InputGroup` and `Toggle` all take `size` (`sm` = h-7, `xs` = h-6) which sets both height and radius — a hand-set `h-7` on a control leaves the radius wrong. Multi-line fields (`Textarea`, combobox chip input) sit on the `h-8` tier (`rounded-xl`), never `rounded-2xl`. Floating containers (menus, popovers, select/command popups) `rounded-xl`; `rounded-3xl` only for the command-palette dialog + chat bubbles. Concentric rule for nested pills: inner ≈ outer − padding (an `InputGroupButton` sitting `rounded-lg` inside a `rounded-xl` group is that rule, not a mismatch). **A control placed under or beside a surface takes that surface's tier** — a `size="sm"` (`rounded-lg`) button beside an `h-8`-row list card (`rounded-xl`) reads as a different family — with one exception: a button that *adds* to the surface above it sits a tier below it, never level with it — the `+ Add value` under an editable list card is `size="sm"`, so it reads as a control serving the card rather than a fourth row broken loose from it ([patterns.md](patterns.md) — editable value lists). `Skeleton` defaults to `rounded-md`: it stands in for text lines far more often than for a control, and every call site that wanted something rounder already says so.
