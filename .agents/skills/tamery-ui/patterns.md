# Native macOS patterns

Paths under `apps/app/src/routes/_protected/connection/$resourceId/` written relative to it.

- **Window dimming**: `.electron.window-blurred` on `<html>` (`electron` class set in `index.html`, `window-blurred` toggled by `use-window-focus-observer.ts`) swaps `--primary` to gray in globals — accent chrome dims for free when token-based. No transition (AppKit snaps).
- **No root rubber-band**: `body` `overscroll-none`; inner scrollers keep native bounce.
- **Context menus** — all via `AppContextMenu` (`apps/app/src/components/app-context-menu.tsx`), data-driven `AppMenuNode[]` tree, NOT raw `@tamery/ui` kit primitives. Web renders base-ui kit; desktop pops OS-native menu over IPC (`window.electron.menu.popup`, main-side `Menu.buildFromTemplate`). Web-only fields: `icon`, `shortcut`, `trailing`, `className`, destructive-red `variant`. Native-only: `accelerator` (display hint), `nativeLabel` (fold trailing info into text), `checked` (checkbox checkmark — active header-cell sort). `contentProps` (`side`/`align`/`className`) + `render` (merge into existing element, e.g. header cell div) web-only; native ignores. Controlled sites pass `open`/`onOpenChange` (native drives them imperatively around the popup). Destructive item last after separator. Right-click on rows/tabs/table column headers/cells/connection cards; chevron dropdown rejected. Open state: `data-popup-open:bg-accent` (base-ui sets on web; wrapper sets on desktop while native menu open).
- **Control family** (outline Button, SelectTrigger, Input, InputGroup, Checkbox — kit level; h-6 chips use `shadow-2xs`): **no border; definition = `bg-input` + `shadow-xs` + half-pixel hairline `ring-[0.5px] ring-foreground/4`**. Hover/open/expanded = **foreground-mix**: `bg-[color-mix(in_oklch,var(--input),var(--foreground)_3%)]` filled, `bg-foreground/5` ghost — foreground flips per theme, so one construction darkens in light / lightens in dark (accent-based and lighten-only hovers rejected). Focus overrides the ring slot (`focus-visible:ring-3 ring-ring/30`), back to hairline on blur. Border slot stays `border-transparent` so focus ring doesn't shift layout — **no `bg-clip-padding` on hairline-ringed controls**: clipping leaves a 1px gap between bg and ring, ring floats (bit us in dark mode); bg must extend under the transparent border. Floating panels: `shadow-lg ring-1 ring-foreground/4`, no borders; structural panes/cards keep hairline `border`. Sizes only via props (`size="sm"` → h-7 rounded-lg, default → h-8 rounded-xl) — never per-page `h-*`. Selects `font-normal`, buttons `font-medium`.
- **Menus compact**: kit defaults (`min-h-7 py-1 text-sm`) — don't re-inflate or shrink. **One radius inside a popup: rows and search field both `rounded-lg`**, shell `rounded-xl` (control family's h-7 → `rounded-lg` mapping; every row is `min-h-7`). `CommandInput` keeps `h-8!` but takes `rounded-lg` explicitly — inside a menu it's a row among rows, not a page control. `xs` select variants keep `rounded-sm`.
- **Menu item icons dimmed**: leading icons in dropdown/context/menubar **and command** items are `text-muted-foreground/60` — the label carries the item; full `text-muted-foreground` glyph columns read as loud as the words. Enforce kit-level on the item (`*:[svg]:text-muted-foreground/60`; destructive/checked/selected variants keep own color — `CommandItem` promotes icons to `text-foreground` on `data-selected`), never per-instance className (hand-set color opts out of the next tuning pass). Icons in items usually need no `className` at all (kit sizes `size-4`). Submenu chevrons + trailing `CommandShortcut`/accelerators muted too.
- **Popovers size to content**: `w-auto min-w-40`; `CommandInput` only at ~8+ items; hide group headings when one group.
- **Grouped lists** (dashboard, `_protected/-components/connections-list.tsx`): one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`. Sections (labels/types): micro-label header per section, one container each, ungrouped last.
- **Tab strip** (`-components/tab-bar.tsx`): Finder-style — content-width tabs, no truncate, each `border-r border-b`, active `border-b-transparent bg-background`, bar `bg-body/50`, trailing filler `div` keeps `border-b` running to the edge (active tab reads as raised notch). One strip for every view type; type shows only via leading icon (`TAB_ICONS`, `size-3.5`, muted → `text-primary` active) + label — no per-type color/badge/border. Labels disambiguate only when needed: table tabs drop schema prefix unless two schemas open; query (only multi-instance type) gets trailing ordinal from second onward — never "Query 1" when there is one. Other types singleton — re-trigger focuses existing tab. Preview italics table-only. Leading toolbar (sidebar toggle, history nav, contextual refresh) in own `border-r border-b` cell before the strip; trailing cell mirrors it **at the far right edge of the bar** (`border-l border-b px-1 gap-0.5`: new-tab `+`, then the AI-chat latch) — flex-1 filler goes between strip and that cell, not after, so it holds the corner at any tab count (following the tabs drifted left, read as stray control). Consequence: every tab keeps `border-r` (old `isLast` prop gone) — last tab borders the filler, not the trailing cell's `border-l`. Contextual controls stay mounted, go `disabled` when N/A (refresh on a query tab) — unmounting reflows the toolbar on tab-type switch. Refresh is **the toolbar's job for every tab type that can refresh**, dispatched by one `TabRefresh` switching on the active tab: table tabs invalidate row/column/total set, definitions tabs invalidate that section's query (`DEFINITIONS_QUERY_OPTIONS` maps section → query options), visualizer invalidates tables-and-schemas + all columns + constraints. Definitions pages carry **no refresh button of their own** — `DefinitionsHeader` is a bare `h2`: page-level + chrome-level buttons for the same data read as two different refreshes, and both on ⌘R would fire twice. General rule: **a control that exists in the window chrome must not be repeated inside the page it acts on.**
- **Tab rename** (same file): **double-click renames** (promotes a preview tab first). Tab swaps `<span>` for bare `<input>` in the same chrome; button element becomes `div` for the duration (input inside button invalid, fights press-nav). **Tab must not resize entering edit mode**: editing container keeps the button's exact classes (same `pr-8`), input fully unstyled — `field-sizing-content min-w-4 border-none bg-transparent p-0 outline-hidden`, inherits font/italic/color; any padding/border/ring shifts the text start and the tab jumps under the cursor. Autofocus + select-all; Enter/blur commits; Escape cancels; empty or equal-to-derived-label clears the override. Reorder drag disabled while editing. Context menu: `Rename`, plus `Reset Name` only when an override exists.
- **Sidebar holds no action icons** (`-components/navigator/`) — it once had six buttons across two rows and read as a control panel. General rule: **an action belongs to the surface it changes, not the surface you were looking at.** New query → ghost `icon-sm` `+` in the tab bar's trailing cell (spec above), **outside** the scroller. The `+` is a **new-tab dropdown** (`NewTabMenu` in `tab-bar.tsx`): New query first, "Schema" group (Visualizer + definitions sections, reusing `schemaGroups` from `navigator/definitions-section.tsx`), "Tables" group (schema-prefixed only when several schemas — same rule as tab labels), content `max-h-[70vh] overflow-auto`; no tooltip (trigger-opens-menu rule). Rejected shapes: labeled `＋ New query` cell (too wide for repeating chrome), outline button atop sidebar, icon button beside list switcher — creating a tab reads best where tabs live. Query logger → title bar's trailing cluster (`_protected/-components/protected-titlebar.tsx`), beside the command palette, only when a `resourceId` is in the route, latched `bg-foreground/10 text-primary` — toggles a window-spanning panel, so belongs to window chrome. Open-in-web → same cluster, desktop + cloud non-localhost only; was a `⋯` overflow menu until one item was left — **a menu with a single item is just a button with an extra click** — then followed the logger out (reopens the whole window elsewhere → window chrome). Show-system-tables lost its UI, kept plumbing: `connectionResourceStore.showSystem` still feeds `resourceTablesAndSchemasQueryOptions` (and its query key), default `false`, awaiting a settings page — deleting the toggle is a UI change; deleting the parameter would be a data change, worth separating. Sidebar keeps: switcher, search, refresh. Consequence: ⌘B hides no actions anymore.
- **Sidebar footer** (`navigator/navigator.tsx` `NavigatorFooter`): the no-action-icons rule's one carve-out — pinned footer of **labeled rows, not icon buttons**, below the list body, outside the tables/schema crossfade so it survives the swap. Rows use the switcher's exact shape (ghost Button `h-7 w-full justify-start gap-2 rounded-md px-2 font-[450]`, muted `size-4` icon): `＋ New query` (press-nav via `pressNavProps`, same `openRunnerTab` navigate as the tab strip's `+` — a duplicate entry point the owner accepted; the chrome rule against repeating controls applies to page bodies, not a second location in chrome) and `⚙ Settings`, `disabled` until the settings page exists. Wrapper `px-2 pt-1.5 pb-0.5` — bottom mirrors the column's `pt-0.5` top inset. Icon rows become labeled rows here: a footer is a menu, not a toolbar.
- **Sidebar list switcher** (`navigator/navigator-switcher.tsx`, `navigator/definitions-section.tsx`): body swaps **Tables** ↔ **Schema** lists, driven by **one morphing row** above the search field — full-width `h-7 rounded-md` ghost Button showing `⧉ Schema ›` / `‹ Tables`. Same control both states: label + icons crossfade with 6px slide in the push direction (`AnimatePresence mode="popLayout"`, 150ms house curve); body swap `opacity` + 12px `x`, 180ms. Which list shows = **session state, never persisted** (in-memory `getNavigatorStore`) — reload lands on Tables (an app parked in a secondary view reads as losing your place). Whichever element leads the sidebar takes `pt-0.5`, not `pt-2` (sidebar shares the page's `m-2`; a full step starts the column 8px below the pane). Resize handle: `w-px` bar inside `px-2` wrapper — hairline visual, 17px grab target. Column `pr-2.5` is derived, not picked: bar sits 8px off the pane, rows need `bar offset − their own px-2` for the same gap. Re-derive when the bar width changes.
- **Naming the second list**: **Schema**, not "Definitions" — the visualizer lives in it (first group `Overview`, then Structure / Types / Logic / Security); the umbrella must cover views as well as objects. General rule: **a growing pile of footer rows means the second list needs a broader name, not more footer.** Rows = standard `SidebarMenuButton` (h-7, `rounded-md`, solid `bg-primary` active, single click preview / double promote) with **muted icons, not `text-primary/75`** — distinct glyphs in blue read as noise; the tables tree repeats one glyph so its blue reads as texture. Own filter field (same `bg-input/60 h-7` InputGroup as tables search), rows grouped under `text-xs text-muted-foreground` headers. Rejected: permanent collapsible group under the tree (ate ~200px of a 256px sidebar), compact icon strip (no room to grow), labeled dropdown (a select implies picking an attribute, not going somewhere), switcher in the same ghost icon row as tab actions (three meanings, one shape).
- **A trigger that opens a menu takes no tooltip** — the menu names its own items, layers collide. Corollary: don't split one concept into `+` plus caret; either the button acts or it opens a menu.
- **Sort popover** (`-tabs/table/-components/toolbar/actions/actions-order.tsx`): one `Command` in a `w-72 p-0 gap-0` popover — `CommandInput` on top (placeholder `Sort by…` → `Then by…` once something is sorted), then **one** `CommandList` with two `CommandGroup`s: `Sorted` (active columns) and `Columns`/`Then by` (rest). **Active sorts live in the list, not a hand-rolled block above the input** — a pinned block outside `CommandList` is invisible to the filter and unreachable by arrows. **No separator between the groups** — headings + filled search field are already the break; a rule plus `my-1` stacked ~16px of dead air against 28px rows. Every row is a `CommandItem`: **sort state is a glyph on the row and pressing is the toggle** — sorted row shows its arrow, flips ASC/DESC on select; unsorted shows a ghost `↑` fading in on `group-data-selected/command-item:` (hover and keyboard); ordinal from the second sorted column onward ("1" alone tells you nothing). Trailing arrow/type goes inside `CommandShortcut` — also suppresses the kit's trailing check (`group-has-data-[slot=command-shortcut]/command-item:hidden`); a row wanting its own trailing meta must use it, not a bare span. **The hover-only ✕ is never the only way out**: the ✕ on a sorted row is always visible (`text-muted-foreground/60`, `hover:bg-destructive/10`) — a destructive control existing only under the cursor gets reported as missing — and `⌫`/`Delete` removes the highlighted sort while the search is empty (handled on the `Command` root; `value`/`onValueChange` and `CommandInput`'s `value` both controlled to tell "highlighted row" from "editing text"), advertised in a `border-t px-2 py-1.5 text-2xs` footer strip. A `Clear sorting` row was cut: with an always-visible per-row ✕ it's a second way to say the same thing. A trailing control nested in a `CommandItem` must `stopPropagation` on **both** `onPointerDown` and `onClick` — cmdk selects on click; without it the ✕ silently flips direction instead of removing. Same pass compacted every popup surface kit-wide: `CommandInput` `h-8!` → `h-7!` (a search field in a menu is a row, not a page control), `Command` root lost its `p-1`, menu `Separator` `my-1` → `my-0.5`, `CommandEmpty` `py-6` → `py-4`. Row height untouched (`min-h-7 py-1`) — compaction removes stacked padding and dead air, never shrinks rows. **The row is the button**: the whole `h-7 rounded-lg hover:bg-accent` row flips direction on click; the arrow is a bare glyph inside it (`text-muted-foreground` → `text-foreground` on row hover), never its own ghost button — ghost `bg-foreground/5` on top of a hovered row's `bg-accent` is a grey slab in a highlight; the second box is the ugliness, not the tint. Only the remove ✕ keeps its own ghost button (different action, fades in on hover). `data-mask`ed name sits between them. The replaced version had a segmented ASC/DESC pill per row and reached the column list through a nested popover. Lessons: **a two-state control in a menu row is one flipping icon, not a pill with both states drawn**; **a picker inside a popover belongs in that popover's own body, never a child popover**. **Every child of `Command` lands on the same left edge, and that edge is 4px** (same inset as `DropdownMenuContent`). The kit `Command` root carries **no padding** — inset comes from `CommandGroup`, the `CommandInput` wrapper, and any hand-rolled row block each carrying `p-1` (a root `p-1` on top pushed command popovers 4px wider/8px taller than the dropdowns beside them, and a row block that forgot its `p-1` sat visibly proud). Separators are the exception: they hang off the root and take `-mx-1` to bleed to the popup edge. A row with a trailing control keeps the control **absolutely positioned inside** the row's surface (`pr-8` + `absolute right-1`), never a flex sibling — a sibling eats width from the hover surface.
- **Table toolbar** (`-tabs/table/-components/toolbar/toolbar.tsx`): filter field flex-1 left, delete-on-selection, columns/sort, `⋯` overflow. `items-end` so buttons stay anchored while the field grows upward. **Counters are outline Buttons in the dock row, not a readout pill** — rows (`TableStats`) left of the flex-1 field, columns (`ActionsColumns`) in the right cluster, both `variant="outline" gap-1.5 px-2.5` with a `text-muted-foreground/60` icon and a `text-2xs font-normal tabular-nums` count. **Counter icons must not collide with chrome glyphs**: rows uses `RiHashtag`, not `RiMenuLine` — three bars beside a bare number reads as a hamburger menu and gets clicked expecting one. **Counters are indicators — count always visible, geometry always stable** (owner decision; count-on-deviation tried and rejected): the columns button always shows `columns.length`, hidden detail lives in the tooltip; the sort button always shows its active count, `0` included — rolling `0 → 1` beats a control that morphs. Counter numbers render through the kit `NumberFlow` (`packages/ui/src/components/custom/number-flow.tsx`) so a changing count rolls instead of snapping — **never `@number-flow/react` directly**: the wrapper halves the library's stock timings (transform 900→450ms same spring curve, opacity 450→225ms; spin follows transform), which read as slow-motion at app scale. App-wide decision, both apps; re-exports `NumberFlowGroup`. In a `visible/total` pair the **changing** number must be the `value` and the stable one the `suffix` (`9` + `/10`) — prefix/suffix are plain text, a count parked there snaps instead of rolling. Derive hidden counts by intersecting persisted hidden ids with the loaded columns — raw store length counts before columns load (rendered `-6/0`) and after schema changes drop columns. A toolbar control must not morph with state — no icon-only ↔ with-count size swap, no state-dependent icon color, no count badge popping in (badge tried and dropped: notification look, and an appearing overlay is still a morph); that reads as a different control appearing, not the same one updating. Rows, columns, sort share one identical shape: `variant="outline" gap-1.5 px-2.5`, muted icon, NumberFlow count. The rows count marks its one interactive state — estimated, click for exact — with a dotted underline (`underline decoration-dotted decoration-muted-foreground/50 underline-offset-2`) on the number: tooltip-only affordance on a permanently-mounted button is invisible. Each count lives on the control that acts on it (rows → exact count, columns → visibility popover); a two-segment `bg-input` pill holding both was tried and dropped — it read as chrome unlike everything else on the line, and split one number from the button that owned it. Row totals use `NumberFlow` compact notation with the locale-grouped number in the tooltip: abbreviate in the button, precise in the tooltip, so a counter's width never drives the neighbor's layout. **Tooltip anchors on the button itself**, never a wrapper around several segments — a tooltip hung off the outer box points at the middle of a group and describes things the cursor isn't on. **The spent state is `disabled` + `disabled:opacity-100`, never a swap to a span**: the rows button only acts while `!exact && total.isEstimated` (clicking an estimate upgrades it to a real `COUNT(*)`), and conditionally rendering a span instead drops the Button's transparent border and box, so it visibly resized the moment you clicked it — one element with the interactivity toggled keeps the geometry identical, `disabled:opacity-100` stops the kit dimming a count that's still worth reading, and `pointer-events-none` from `disabled` lets a `TooltipTrigger render={<span className="flex"/>}` wrapper keep serving the tooltip. Padding moves from the shell to the segments (`px-1` + `gap-1` outside, `px-1.5` per segment) so the hover surface has room without shifting the text: the old `px-2.5 gap-4` insets are reproduced exactly (4+6 = 10px edge, 6+4+6 = 16px between). **`exact` is plain `useState` in `TableToolbar`**, deliberately out of the localStorage `tablePageStore` — an exact count is a one-off answer about right now, and persisting it made every later visit silently pay for a full scan. It stays local because nothing else needs to *read* it: the sites that used to (tab refresh, delete, seed, the route loader's prefetch) only ever needed to invalidate or warm the total, so they take the prefix `resourceTableTotalQueryKey(...)` / `exact: false` instead. **A cross-component store to keep an invalidation key in sync is the wrong fix** — invalidating by prefix matches every variant and can't go stale, and threading the flag out only existed to reconstruct a key by hand.
- **Empty states**: kit `Empty` primitives (`Empty`/`EmptyHeader`/`EmptyMedia`/`EmptyTitle`/`EmptyDescription`/`EmptyContent`), never a hand-rolled div stack, house sizing on top of registry defaults — media `size-14 rounded-2xl bg-muted/60` with `size-7 text-muted-foreground/70` icon (the `icon` variant's `size-10 rounded-lg bg-muted` is registry-sized), title `text-sm font-medium`, description `text-xs`. Block fades/scales in (`opacity 0→1`, `scale 0.97→1`, 250ms house curve) via `motion.div` wrapping header + content; container keeps `Empty`'s centering. **A pane-level empty state is icon + title + one line, nothing else** (no-open-tab pane `connection/$resourceId/index.tsx`): no buttons, action lists, shortcut hints. Rejected in order: side-by-side Buttons (forced either/or), grouped-list card of `Item` rows (heavier than the emptiness it explains), bare `⌘P`/`⌘B` kbd. **Anything added to an empty pane competes with the emptiness, and the emptiness is the message.** Controls belong to the chrome that owns them; the pane only says what's missing and where to look. `apps/app/src/error-page.tsx` sets the copy voice.
- **Shortcuts**: only via `packages/ui/src/components/custom/shortcuts.tsx` (`KbdCtrlLetter`, `KbdBackspace` etc., pass `userAgent` where the glyph is platform-dependent). Never hand-roll ⌘/Ctrl. **A key is a Remix glyph, never the unicode character** — a literal `⌫`/`⌘` renders at the font's own weight and optical size, oversized next to `text-2xs`. New key → add to `shortcuts.tsx`. **A passive hint line takes the bare glyph, not a `Kbd`** — the boxed key belongs where a shortcut is advertised as pressable chrome (menu rows, palette footers); a muted hint under a list is prose. Sort popover footer: `border-t px-2 py-1.5 text-2xs text-muted-foreground/70`, `size-3` glyph, no chip. Only advertise shortcuts that fire — gate Electron-only (⌘R) on `window.electron`.
- **Tooltips**: never nest triggers; `TooltipContent` is `inline-flex` — wrap multi-line content in `flex flex-col gap-0.5`.
- **Toasts** (`sonner.tsx`): `unstyled: true` + Tailwind classNames — glass (`rounded-xl bg-background/80 p-3 shadow-lg ring-1 ring-foreground/4 backdrop-blur-xl`), filled Remix icons in semantic colors. Never sonner's default theme.
- **Copy**: kit `CopyButton` (copy→check morph); silent `copy(text)` when the morph is confirmation enough.
- **Interactive icons — app-wide rule**: hover surface (`ghost` icon Button + `hover:bg-foreground/5`), icon `muted → foreground`, `Tooltip` naming the action; latched `bg-foreground/10 text-primary`. Toggles (pin/unpin) swap icon on button hover (`group/pin` + hidden/block pair). In cmdk rows: reveal via `group-data-selected/command-item:opacity-100` (keyboard too), wrap the button in `CommandShortcut`. Ref: `ResourceRow` in `connections-list.tsx`. Upgrade bare icons whenever touching a file.
- **Count badges**: absolute `-top-1.5 -right-1.5 h-4 min-w-4 rounded-full bg-primary text-2xs`; Button needs `relative overflow-visible`. Not for toolbar counters — those show the count inline, always, `0` included (see table toolbar).
- **Upsell/hero dialogs** (`apps/app/src/components/subscription-modal.tsx`): centered — glow icon chip (`size-14 rounded-2xl bg-primary/10 inset-ring inset-ring-primary/15`, filled Remix icon, behind it `absolute -inset-5 rounded-full bg-primary/20 blur-2xl`), `text-lg` title, one-line muted description, perks as `rounded-xl bg-foreground/3 divide-y divide-foreground/5` list (primary icons, `text-sm` labels), footer buttons `sm:flex-1` full-split, `text-xs` centered footnote. Top wash `bg-linear-to-b from-primary/8 via-background via-40%`. Copy minimal — no paragraph selling.
- **Nav fires on mousedown, not click** (instant, Linear-style). **Always import `Link` from `~/components/link.tsx`, never `@tanstack/react-router`.** `createLink` wrapper: synthetic `.click()` on mousedown, swallows the real follow-up click in the capture phase — told apart by `e.detail` (synthetic `.click()` and keyboard Enter = 0; real mouse click ≥ 1). Guards preserve cmd/ctrl/shift/alt-click (open-in-new-tab), skip `target=_blank`. **Menus are the exception** — base-ui `DropdownMenuItem render={<Link/>}` must pass `activateOn="click"` for native mouseup activation (macOS menu semantics). Imperative press-nav on plain buttons/tabs: spread `pressNavProps(fire)` from `~/lib/press-nav.ts` (`onMouseDown` on plain press + `onClick` keyboard fallback via `detail 0`); a nested click target (tab's close ✕) gets `onMouseDown={e => e.stopPropagation()}` so the press doesn't navigate first. Ref: `tab-bar.tsx` `Tab`. **Draggable elements keep press-nav** — grab-to-reorder also focuses, intended (Finder/Chrome same). Mouseup-with-drag-slop variant tried and reverted: loses instant feel, and the second mouseup of a double-click blurs the rename input the instant it mounts — inline rename silently broke.
- **Dialog rails**: `SidebarLink`/`SidebarButton` from `~/components/sidebar-link.tsx` — `h-7 rounded-md text-sm`, solid `bg-primary` active. (Sidebar lists themselves use `SidebarMenuButton` from `navigator/primitives.tsx`.)
- **Unified filter field** (`-tabs/table/-components/toolbar/filter-search-bar.tsx`): input-styled container (`min-h-8 flex-wrap bg-input rounded-xl`, `has-[input:focus]` ring), chips inline + bare `CommandPrimitive.Input`. Suggestion panel opens upward (`absolute bottom-full mb-2 bg-popover rounded-xl`, kit `CommandList` in unstyled `CommandPrimitive`); `onMouseDown preventDefault` keeps focus. **Panel shell carries no padding of its own** — `CommandGroup`'s `p-1` is the inset; a shell `p-1` on top doubled every edge to 8px (same reason the kit `Command` root has none). The hand-rolled AI-summary row takes `m-1` to land on the items' left edge. Summary enters sliding up (`height 0→auto`, `y 8→0`, fade, 200ms house curve) and exits back down via `AnimatePresence`; height animates on an `overflow-hidden` outer `motion.div` with padding/border on an inner div (padding on the animated element breaks `height: 0`). The panel shell itself is inside `AnimatePresence` with a 150ms fade/`y: 8` exit (`initial={false}` — opening stays instant) so a summary-alone shell doesn't snap away mid-exit and blur gets a soft close. Stage machine column → operator → value; panel runs `shouldFilter={false}`, so **suggestion order is JSX order and nothing rescues a bad one** — column matches first, ranked exact → prefix → substring (typing `id` puts `id` above `user_id` regardless of column order); `Ask AI: "…"` sits under them (was on top, stole the first slot from the literal column just typed). First row = the answer the query already names; open-ended help last. Pending chip styled like committed chips minus eye/✕. **Chips scroll, the field doesn't grow forever**: the wrapping row is its own `scroll-fade no-scrollbar max-h-32 overflow-y-auto` scroller holding chips + stage chip + input, with the search glyph and `⌘F` hint as fixed siblings outside it (they must never scroll away); past ~5 rows it scrolls with mask fades at both edges, and an effect pins `scrollTop` to the bottom whenever a filter is added so the input stays in view. Without the cap a dozen filters push the table off screen. Value stage adds "Suggested values" (enums via `column.availableValues`, booleans true/false) — pick applies immediately, or toggles into the comma list for `isArray`. Backspace on empty steps back / pops last chip; ⌘F focuses; Escape cancels stage then blurs. **AI results report themselves inline, not by toast**: `Ask AI` rewrites filters and ordering at once and chips alone don't say what changed (ordering has no chip) — `onSuccess` builds a one-line summary (`Applied 2 filters on name, created_at · sorted by created_at desc`) rendered as a pinned header **outside `CommandList`**, first child of the panel shell (full-bleed `border-b` while the list is open, `px-3` so its text lands on the items' text edge, drops in from `y: -4`), muted `text-xs` with a `text-success` check, `data-mask`ed (names columns). Clears after 6s or next keystroke. **It must not live inside the scrolling list**: the list is `max-h-64` and the AI clears the query, so the panel reopens showing every column and a summary row at the list's end sits below the fold — invisible for its whole 6s.
