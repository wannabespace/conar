# Native macOS patterns

- Window dimming: `.electron.window-blurred` swaps `--primary` to gray in globals — token-based chrome dims for free. No transition (AppKit snaps).
- `body` `overscroll-none`; inner scrollers keep native bounce.
- Context menus: always `AppContextMenu` (data-driven node tree; web renders base-ui, desktop pops native menu over IPC), never raw kit menu primitives. Destructive item last after a separator.
- **Control family** (kit): no border — `bg-input` + `shadow-xs` + hairline `ring-[0.5px] ring-foreground/4`. Hover = foreground-mix (3% filled, `bg-foreground/5` ghost), never accent-based or lighten-only. Border slot stays `border-transparent` (focus must not shift layout); **no `bg-clip-padding` on hairline-ringed controls** (opens a 1px gap). Floating panels take the same `ring-[0.5px] ring-foreground/4` hairline, no borders, `shadow-xl` (`shadow-lg` reads as flat paper on light); menu/select/combobox shells `p-1`.
- Popup radius: rows and search field `rounded-lg`, shell `rounded-xl`; kit density defaults — don't re-inflate or shrink. Menu rows (dropdown, context, menubar, select, combobox, command): `text-sm font-[450] tracking-wide` — 450 matches navigator rows and the tab bar (400 reads too light beside the chrome). Leading icons `size-4 text-foreground/70`, enforced kit-level (`/60` reads as watermarks beside near-black labels). Toolbar-button and tab glyphs keep `/60`. Separators `-mx-1.5 my-1`.
- Popovers size to content (`w-auto min-w-40`); `CommandInput` only at ~8+ items; hide a sole group heading.
- Grouped lists: one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`.
- Divider between chrome-strip control groups: kit `<Separator orientation="vertical" className="mx-0.5 h-4!" />`, never a hand-rolled `bg-border w-px` span (kit vertical defaults to `h-full`; the `!` is explained in [gotchas.md](gotchas.md)).
- **32px chrome strips** (tab bar, chat header, logger header): buttons `size="icon-xs"` with `size-3.5` glyphs — `icon-sm` fills the strip and its hover square reads as a slab, even beside full-height tabs. Anything full-height inside the strip sizes to the header's *content* box: `h-full`, never a literal `h-8` (spills 1px over the `border-b`). End cells `px-1`.
- **Tab strip**: Finder-style — content-width tabs, active tab = raised notch; type shows via leading icon only, no per-type color/badge. Labels disambiguate only when needed (schema prefix at 2+ open schemas; query ordinal from the second instance). Trailing cell (`+` menu, chat latch) pinned to the bar's far right edge. Contextual controls stay mounted and go `disabled`, never unmount. **A control in the window chrome must not repeat inside the page it acts on** (refresh: SKILL rule 10).
- **Pane-edge tab strips** (logger detail): `TabsList variant="bar"` — flat full-height cells on `bg-body/50` (same `text-sm px-3` as the window tab bar — a smaller `text-xs px-2.5` step was tried and reverted), active cell `bg-background` with no shadow or side borders, so it reads as a notch in the pane edge rather than a segmented pill.
- Tab rename: double-click (promotes preview first); the tab must not resize entering edit mode — unstyled `field-sizing-content` input inside the same container classes. Empty or equal-to-derived clears the override.
- Navigator sections pad `pl-2` only; their right inset is the panel's own gutter (`pr-1.5`, see resize handles).
- **Sidebar holds no action icons** — **an action belongs to the surface it changes, not the surface you were looking at.** New tab → tab strip's `+` dropdown; window-spanning toggles → title bar. Footer = labeled rows, never icon buttons (a footer is a menu, not a toolbar). **A menu with a single item is just a button with an extra click.**
- Tables ↔ Schema switcher: one morphing row above search; which list shows is session state, **never persisted** (reload lands on Tables). Second list is named **Schema** — the umbrella must cover the visualizer too. List rows use muted icons, not primary (distinct glyphs in blue read as noise).
- **A trigger that opens a menu takes no tooltip** — the menu names its own items; either a button acts or it opens a menu, never `+` plus caret.
- **Command popups** (sort popover): active state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row; no nested ghost buttons except the remove ✕). **A hover-only ✕ is never the only way out.** A nested trailing control `stopPropagation`s on both `onPointerDown` and `onClick` (cmdk selects on click) and sits absolutely inside the row, never as a flex sibling. A two-state control in a row is one flipping icon, not a pill with both states; a picker belongs in the same popover's body, never a child popover. Every `Command` child lands on the same 4px left edge — the root has no padding, each section carries its own `p-1`.
- **Table toolbar counters**: outline Buttons sharing one shape, each count on the control that acts on it. **Count always visible, geometry always stable** — no morphing, no popping badges; a `Skeleton` bar before the count is known (a premature `0` is a wrong answer). Numbers roll via the kit `NumberFlow` wrapper only (stock timings read slow-motion); the changing number is the `value`, the stable part the `suffix`. Tooltip anchors on the button itself. Spent state = `disabled` + `disabled:opacity-100`, never a span swap (geometry must not change). Invalidate by query-key prefix — never thread state around to reconstruct a key.
- Empty states: kit `Empty` primitives; a pane-level empty state is icon + title + one line, nothing else — **anything added competes with the emptiness, and the emptiness is the message.**
- Shortcuts: kit `shortcuts.tsx` only; **a key is a Remix glyph, never the unicode character**; passive hint lines take the bare glyph, not a `Kbd`; only advertise shortcuts that fire (gate Electron-only on `window.electron`).
- Tooltips: never nest triggers; `TooltipContent` is `inline-flex` — wrap multi-line content in a flex column.
- Global banner (`global-banner.tsx`): slow and broken connections report here — a page that only spins is the bug. Slow banner shows live elapsed seconds; the reconnect banner suppresses it; wording is about the response, never "connecting".
- Toasts: `unstyled: true` + glass recipe, never sonner's default theme.
- Interactive icons app-wide: ghost hover surface + muted→foreground icon + tooltip; latched `bg-foreground/10 text-foreground` ([colors.md](colors.md)). Upgrade bare icons whenever touching a file.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics); imperative press-nav via `pressNavProps`.
- **Filter field**: suggestion order is JSX order (`shouldFilter={false}`) — the literal answer first, `Ask AI` last. Chips scroll in a capped row (the field must not grow forever). AI results report inline as a pinned header above the list — never a toast, never inside the scrolling list. Quota exhaustion disables only the `Ask AI` item, never the input. Blur keeps the in-progress stage; only Escape steps back. Chips read in prose (`Is not null`), never raw SQL.
- Dither shader: **auth layout only** — an animated background never sits under a card, and each instance is a WebGL context. `dither-in` entrance is the only other carrier — **dithering governs entrances, never resting chrome** (grain on resting surfaces reads as the transparency checkerboard / dirt).
- Title-bar switchers: workspace rows are submenus whose trigger still switches on click — hand the destination over directly, no switch-then-hunt. Subscription-gated actions render enabled and route to the upsell modal — the modal is the gate, not a greyed item.
- Data table: ghost cell controls only (outline buttons down a column fight the values); **no vertical rules, header included** (zebra + hover = macOS list; rules = spreadsheet). Skeleton bars (table, navigator) deterministic via kit `pseudoRandom` (`@tamery/ui/lib/utils`) seeded by index, never `Math.random`.
- Markdown: kit `Response` only; the chat does **not** pass `streaming` (per-block memoization restarts the word fade every block). Fenced code = kit `CodeBlock` via `components={{ pre }}`, 10-line peek with expand.
- **Resize handles**: **every pane split is a `react-resizable-panels` group** (kit `ResizablePanelGroup`/`ResizablePanel`/`ResizableHandle`; fold recipe in [motion.md](motion.md)); the px-driven kit `ResizeHandle` survives only for table column resizing. `ResizableHandle` is a transparent grab strip around a 2px line — invisible at rest, `bg-border` on hover, `bg-primary/40` while dragging; no permanently visible grip. The line sits mid-gutter (flush against a pane it reads as a second border); the grab target never overhangs the content pane. **The gutter lives inside the collapsible panel** as its padding, so it folds with the content, and the separator overlaps it with a negative margin — the separator adds nothing to the group's total, so collapsing never shifts the other panels. Two-panel groups (runner results, logger detail) keep the plain in-flow separator, shrunk to zero when `disabled`. Persisted sizes (`navigator-width`, `chat-width`, `logger-height`) include the gutter, feed back as `defaultSize`, refresh from `onResize` (px) while dragging; double-click resets via `panelRef.resize(DEFAULT)` with `disableDoubleClick` — the library's own double-click only restores `defaultSize`, which *is* the persisted value.
- **Chat panel**: its header is the chat's share of the window's top row — same `h-8` as the tab bar beside it, same muted ghost icon buttons, so both strips read as one line. Width persists globally (a panel width is a habit, not a property of the database); toggle in the tab bar's trailing cell (a per-resource control sits under the pane it opens); ⌘L lives with the button, not the panel. Open/close is a panel fold ([motion.md](motion.md)) around a pinned-width child (a flex-proportion child rewraps every bubble); content stays mounted at width 0; the panel keeps `overflow: visible` so the card's shadow survives ([gotchas.md](gotchas.md)). Composer textarea owns the whole box with the send control floating over it (an addon row leaves the box's bottom unclickable). Assistant turns render **every** part (text-only join silently loses tool work); user = bubble, assistant = bare `Response` (bubbling both halves the reading width). First-token wait = `Spinner` inside the last turn's item — never a skeleton (length unknown), never its own item (anchor-pass trap, [gotchas.md](gotchas.md)). `scrollAnchor` only on turns this tab sent + provider `autoScroll` — a passive tab syncing the same turn must not inherit the sender's reserved spacer. Spinner whenever the last turn is unanswered, suppressed only by `error`; read `'streaming'`, never `'submitted' || 'streaming'` (the resume probe sets `submitted`) — except the stop button, which arms on send. Switching/new chat aborts nothing — streams detach server-side; the stop button is the only abort. Title falls back to the first user message before `New Chat` (server-generated title syncs late). Live exchange = `useChat`; settled turns = collections merged by id, persisted wins (`api.md`). Chats collections are not awaited in `_protected`'s `beforeLoad`, so the chat reads them with `useLiveSuspenseQuery` under `<Suspense fallback={<ChatSkeleton />}>` — never `useLiveQuery` plus a hand-rolled `isReady` gate (zero rows is ambiguous until sync lands; suspending computes the `resume` decision from real rows).
- **Query logger**: a log list, not a card list — full-bleed `h-7` `Item` rows (`border-0`, [gotchas.md](gotchas.md)), no hairlines, `hover:bg-accent`, selection `bg-foreground/10` (the latched-control tint — hover and selection must differ). Not here: Finder-style solid `bg-primary` rows (a slab when full-bleed, and `primary-foreground` text kills the token colours), zebra, `hover:bg-popover` ([colors.md](colors.md)), a primary edge bar, per-status counter chips in the header. Status is a `size-1.5` dot coloured only for error/pending — success stays `bg-foreground/20`, a column of green competes with the highlighted SQL. Row SQL renders through kit `CodeInline` (shares `CodeBlock`'s highlighter; keep `data-slot="code-block"` for the dark-theme rule); rows are virtualized. Header = title + clear + close; the title-bar toggle is the way back in. Inspecting a row opens a resizable **detail pane beside the list**, never a viewport-wide popover and never a Monaco editor per row. Detail = in-flow `TabsList variant="bar"` (Query / Error / Values / Result · N) over one `CodeBlock collapsible={false} header={false} rounded-none bg-transparent` for the active tab only ([gotchas.md](gotchas.md): base-ui exit stall), copy as glass floating chrome top-right inside the panel, `no-scrollbar scroll-fade` on the scroller, no ✕ — re-clicking the row or dragging the split to zero closes it. Nothing `absolute` inside the folding pane (it twitches during the fold); no second strip (buttons pile up in one corner); no `variant="line"` (its underline floats a second line above the header border). The `Tabs` root wraps the whole logger, so the active tab is state keyed to the shown query id and reset in render — never a `key` on the root, which holds the virtualized list. No code folding: shiki tokenizes, folding is editor behaviour. Params and results print indented, one value per line, length-capped before highlighting. The list/detail seam is a `w-px` `ResizableHandle` with a resting `bg-border` line instead of the gutter — inside one pane an empty gutter reads as rows stopping short; the library's `resizeTargetMinimumSize` keeps it draggable. Open/close is the panel fold ([motion.md](motion.md)) pinned to the stored `logger-height`; content is gated on first open (render-phase state) so the lazy chunk waits, then stays mounted at height 0; the detail panel latches the last inspected query so it never empties mid-fold.
- Floating scroll-to-end control: `variant="outline"`, circle, lifts on hover — the shadow is the feedback; flat tint fills over text read as grime.
- **Boot shell**: `apps/app/src/shell.tsx` renders the chrome the window shows before the bundle loads — one shell per router layout sharing a `ShellFrame` title bar; `Shells` renders the whole set, so adding a layout never touches the plugin. `@tamery/vite-prerender` writes them into `index.html` (wiring: `architecture.md`); `src/boot.ts` is bundled into the head, picks the shell, resolves the theme class and publishes persisted panel geometry as `--shell-*` vars so nothing jumps on swap; `main.tsx` drops `[data-shell]` on the router's first `onResolved`. Rules: shell components stay hook-free and free of browser globals (they render in Node); every class shared with live chrome comes from an exported const (`titleBarClassName`, `resourcePanelClassName`, `centeredPageClassName`), never a copy — that is why the swap is invisible; repeated hooks are data attributes, never ids. `boot.ts` imports only the leaf `lib/storage-keys.ts` and re-parses raw JSON — seitu plus its arktype schema is ~155kB of render-blocking script against ~1.2kB; never retype a key or default. `[data-shell]` visibility rules live **unlayered** in globals.css — inside `@layer base` a `display:none` loses to a `flex` utility. `/create` reuses the dashboard shell; auth content is not prerendered (the page animates itself in). Dev serves the same markup but cannot show the pre-JS paint (dev CSS arrives through the bundle) — check timing against a build.
- **Minimum window size**: `MIN_WINDOW_WIDTH` / `MIN_WINDOW_HEIGHT` in `@tamery/shared/constants` are the one source — Electron's `BrowserWindow` clamps to them and `~/components/window-too-small.tsx` covers the app with an opaque `bg-body` kit `Empty` below them, above dialogs and toasts. Width is the connection layout's floor: navigator `SIDEBAR_MIN_WIDTH` + a usable resource pane + chat `CHAT_MIN_WIDTH` + the window's `p-2`. The overlay stays in the desktop build (the native clamp does not cover browser zoom; the web build has no clamp) and stays draggable (`-webkit-app-region: drag`). Detection is a module-level seitu `createMediaQuery` read with `useSubscription`, never a resize listener.
