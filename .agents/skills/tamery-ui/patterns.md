# Native macOS patterns

- Window dimming: `.electron.window-blurred` swaps `--primary` to gray in globals — token-based chrome dims for free. No transition (AppKit snaps).
- `body` `overscroll-none`; inner scrollers keep native bounce.
- Context menus: always `AppContextMenu` (data-driven node tree; web renders base-ui, desktop pops native menu over IPC), never raw kit menu primitives. Destructive item last after a separator.
- **Control family** (kit): no border — `bg-input` + `shadow-xs` + hairline `ring-[0.5px] ring-foreground/4`. Hover = foreground-mix (3% filled, `bg-foreground/5` ghost); accent-based and lighten-only hovers rejected. Border slot stays `border-transparent` (focus must not shift layout); **no `bg-clip-padding` on hairline-ringed controls** (opens a 1px gap). Floating panels `shadow-lg ring-1 ring-foreground/4`, no borders. Sizes via size props only, never per-page `h-*`.
- Popup radius: rows and search field `rounded-lg`, shell `rounded-xl`; kit density defaults — don't re-inflate or shrink. Menu-item leading icons `text-muted-foreground/60`, enforced kit-level, never per-instance.
- Popovers size to content (`w-auto min-w-40`); `CommandInput` only at ~8+ items; hide a sole group heading.
- Grouped lists: one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`.
- **32px chrome strips** (tab bar, chat header): buttons are `size="icon-xs"` with `size-3.5` glyphs — `icon-sm` fills the strip's full height and the hover square reads as a slab. End cells take `px-1`, so the 4px left over above and below a 24px button is the same gap it gets at the strip's edge.
- **Tab strip**: Finder-style — content-width tabs, active tab = raised notch; type shows via leading icon only, no per-type color/badge. Labels disambiguate only when needed (schema prefix at 2+ open schemas; query ordinal from the second instance). Trailing cell (`+` menu, chat latch) pinned to the bar's far right edge. Contextual controls stay mounted and go `disabled`, never unmount. Refresh is `TabRefresh`'s job for every tab type; pages ship none — **a control in the window chrome must not repeat inside the page it acts on.**
- Tab rename: double-click (promotes preview first); the tab must not resize entering edit mode — unstyled `field-sizing-content` input inside the same container classes. Empty or equal-to-derived clears the override.
- Navigator sections pad `pl-2` only; their right inset is the panel's own `pr-2` gutter, so rows sit 8px from their left edge and 8px from the pane.
- **Sidebar holds no action icons** — **an action belongs to the surface it changes, not the surface you were looking at.** New tab → tab strip's `+` dropdown; window-spanning toggles → title bar. Footer = labeled rows, never icon buttons (a footer is a menu, not a toolbar). **A menu with a single item is just a button with an extra click.**
- Tables ↔ Schema switcher: one morphing row above search; which list shows is session state, **never persisted** (reload lands on Tables). Second list is named **Schema** — the umbrella must cover the visualizer too. List rows use muted icons, not primary (distinct glyphs in blue read as noise).
- **A trigger that opens a menu takes no tooltip** — the menu names its own items; either a button acts or it opens a menu, never `+` plus caret.
- **Command-popup lessons** (sort popover): active state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row; no nested ghost buttons except the remove ✕). **A hover-only ✕ is never the only way out.** A nested trailing control `stopPropagation`s on both `onPointerDown` and `onClick` (cmdk selects on click) and sits absolutely inside the row, never as a flex sibling. A two-state control in a row is one flipping icon, not a pill with both states; a picker belongs in the same popover's body, never a child popover. Every `Command` child lands on the same 4px left edge — the root has no padding, each section carries its own `p-1`.
- **Table toolbar counters**: outline Buttons sharing one shape, each count on the control that acts on it. **Count always visible, geometry always stable** — no morphing, no popping badges; a `Skeleton` bar before the count is known (a premature `0` is a wrong answer). Numbers roll via the kit `NumberFlow` wrapper only (stock timings read slow-motion); the changing number is the `value`, the stable part the `suffix`. Tooltip anchors on the button itself. Spent state = `disabled` + `disabled:opacity-100`, never a span swap (geometry must not change). Invalidate by query-key prefix — never thread state around to reconstruct a key.
- Empty states: kit `Empty` primitives; a pane-level empty state is icon + title + one line, nothing else — **anything added competes with the emptiness, and the emptiness is the message.**
- Shortcuts: kit `shortcuts.tsx` only; **a key is a Remix glyph, never the unicode character**; passive hint lines take the bare glyph, not a `Kbd`; only advertise shortcuts that fire (gate Electron-only on `window.electron`).
- Tooltips: never nest triggers; `TooltipContent` is `inline-flex` — wrap multi-line content in a flex column.
- Global banner (`global-banner.tsx`): slow and broken connections report here — a page that only spins is the bug. Slow banner shows live elapsed seconds; the reconnect banner suppresses it; wording is about the response, never "connecting".
- Toasts: `unstyled: true` + glass recipe, never sonner's default theme.
- Interactive icons app-wide: ghost hover surface + muted→foreground icon + tooltip; latched `bg-foreground/10 text-primary`. Upgrade bare icons whenever touching a file.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics); imperative press-nav via `pressNavProps`. Mouseup-with-slop variant reverted — loses the instant feel, broke inline rename.
- **Filter field**: suggestion order is JSX order (`shouldFilter={false}`) — the literal answer first, `Ask AI` last. Chips scroll in a capped row (the field must not grow forever). AI results report inline as a pinned header above the list — never a toast, never inside the scrolling list. Quota exhaustion disables only the `Ask AI` item, never the input. Blur keeps the in-progress stage; only Escape steps back. Chips read in prose (`Is not null`), never raw SQL.
- Dither shader: **auth layout only** (full product rollout reverted — an animated background never sits under a card; each instance is a WebGL context). `dither-in` entrance is the only other carrier — **dithering governs entrances, never resting chrome** (grain on resting surfaces reads as the transparency checkerboard / dirt).
- Title-bar switchers: workspace rows are submenus whose trigger still switches on click — hand the destination over directly, no switch-then-hunt. Subscription-gated actions render enabled and route to the upsell modal — the modal is the gate, not a greyed item.
- Data table: ghost cell controls only (outline buttons down a column fight the values); **no vertical rules, header included** (zebra + hover = macOS list; rules = spreadsheet). Skeleton bars deterministic via sin-hash, never `Math.random`.
- Markdown: kit `Response` only; the chat does **not** pass `streaming` (per-block memoization restarts the word fade every block). Fenced code = kit `CodeBlock` via `components={{ pre }}`, 10-line peek with expand.
- Resize handles: hairline mid-gutter (flush against a pane reads as a second border); grab target never overhangs the content pane. **Every pane split is a `react-resizable-panels` group** (kit `ResizablePanelGroup`/`ResizablePanel`/`ResizableHandle`, [motion.md](motion.md) for the fold recipe); the px-driven kit `ResizeHandle` survives only for table column resizing. `ResizableHandle` draws a transparent `w-2`/`h-2` grab strip around a 2px line that is invisible at rest, `bg-border` on hover and `bg-primary/40` while dragging, read from the library's own `data-separator` state. The `withHandle` grip pill was removed: a permanently visible grab dot is the one resizer that did not look like the others. **The gutter lives inside the collapsible panel** (navigator `pr-2`, chat `pl-2`, logger `pt-2` on the pinned child, so it folds with the content) and the in-flow `w-2`/`h-2` separator overlaps it with a negative margin (`-ml-2` after the navigator, `-mr-2` before the chat, `-mb-2` before the logger; `relative z-10` so it paints and double-clicks above the panel). Its box therefore adds nothing to the group's total — the version where the separator *was* the gutter and shrank to zero on collapse made every other panel drift a pixel or two during a fold, because the flex total changed while `flex-grow` interpolated. Two-panel groups (runner results, logger detail) have no third panel to drift and keep the plain in-flow separator, shrunk to zero when `disabled` (`aria-disabled:w-0` / `aria-[orientation=horizontal]:aria-disabled:h-0` at the call site). Persisted sizes (`navigator-width`, `chat-width`, `logger-height`) include the gutter, are fed back as `defaultSize` and refreshed from `onResize` (px) while dragging; double-click resets through `panelRef.resize(DEFAULT)` with `disableDoubleClick`, since the library's own double-click only restores `defaultSize`, which *is* the persisted value.
- **Chat panel**: its header is the chat's share of the window's top row — same `h-8` as the tab bar it sits beside, same muted ghost icon buttons, so the two strips read as one line across the window. Width persists globally (a panel width is a habit, not a property of the database); toggle in the tab bar's trailing cell (per-resource control, sits under the pane it opens); ⌘L lives with the button, not the panel. Open/close is a panel fold ([motion.md](motion.md)) around a pinned-width child — a flex-proportion child rewrapped every bubble and was reverted; content stays mounted at width 0. The chat panel keeps `overflow: visible` so the card's shadow survives; the kit clips it only once collapsed and settled, so the parked content never peeks into the window padding (same for the logger). Composer textarea owns the whole box with the send control floating over it (an addon row leaves the box's bottom unclickable). Assistant turns render **every** part (text-only join silently loses tool work); user = bubble, assistant = bare `Response` (bubbling both halves the reading width). First-token wait = `Spinner` inside the last turn's item — never a skeleton (length unknown), never its own item (anchor-pass trap, gotchas.md). `scrollAnchor` only on turns this tab sent + provider `autoScroll` — a passive tab syncing the same turn must not inherit the sender's reserved spacer. Live exchange = `useChat`; settled turns = collections, merged by id, persisted wins (`api.md`). Switching/new chat aborts nothing — streams detach server-side; the stop button is the only abort. Spinner whenever the last turn is unanswered, suppressed only by `error`; read `'streaming'`, never `'submitted' || 'streaming'` (the resume probe sets `submitted`) — except for the stop button, which should arm on send. Title falls back to the first user message before `New Chat` (server-generated title syncs late). Chats collections are **not** awaited in `_protected`'s `beforeLoad` (the route must not block on them), so the chat reads them with `useLiveSuspenseQuery` under a `<Suspense fallback={<ChatSkeleton />}>` — never `useLiveQuery` plus a hand-rolled `isReady` gate. Zero messages is ambiguous until sync lands, and suspending means the transcript-dependent `resume` decision is computed from real rows instead of an empty collection; a gate would have to live in a wrapper component, since hooks can't sit behind an early return.
- **Query logger**: a log list, not a card list — full-bleed `h-7` rows, hairline-free, `hover:bg-accent`, selection as `bg-accent` plus a 2px primary `before:` bar down the left edge — hover and selection share the one tint and the bar alone marks which row is open. The Finder-style solid `bg-primary` row that nav lists use was tried and reverted here: full-bleed across a dense log it reads as a slab, and flipping the text to `primary-foreground` destroys the keyword/rest contrast the row is built on -- a solid active row needs the contained, inset pill shape the navigator gives it. Zebra striping and the level-2 `hover:bg-popover` rule both came out: light theme puts only 1.4% between `--background` and `--popover`, so the hover barely registered and on a striped row it cancelled the stripe instead. Token colors already supply the scan rhythm zebra was there for, and one tint family (accent hover, primary selection) beats three stacked surfaces. Status is a `size-1.5` dot, never a repeated outline icon (eight green check circles down a column is the noise the panel is trying to avoid). Per-status counter/filter buttons were built and removed: three chips reading `19 0 0` spend the whole header on numbers nobody acts on, and the header is now the title plus clear and close alone. Row SQL is shiki-highlighted through kit `CodeInline` — the same private highlighter `CodeBlock` uses, exported rather than duplicated, and it must keep `data-slot="code-block"` or the dark-theme `--shiki-dark` rule in globals stops matching. It replaced a hand-rolled keyword/rest split; real token colors give the scan rhythm a uniform monospace column lacks, and rows are virtualized so only what is on screen tokenizes. Inspecting a row opens a **detail pane beside the list** (resizable), never a viewport-wide popover: the old 95vw popover with two Monaco editors covered the window and mounted an editor per hover. The detail pane is **tabbed** (Query / Error / Values / Result · N), one `h-8` strip carrying `TabsList variant="line"`, the run's duration and time, and its own ✕ — stacking every section instead put three labelled code cards in a 200px pane and buried the scroll. Bodies are kit `CodeBlock` with `collapsible={false} header={false}` and `rounded-none bg-transparent`: the peek-and-expand footer is right for chat prose and reads as a broken scroller in an inspector, the tab already names the content while the strip owns the `CopyButton`, and the default card chrome would nest a box inside the pane. A read-only `Monaco` per tab was tried in between and dropped — an editor instance per inspected row is the weight the old popover was removed for, and its `sql` highlighting only lands when the language id is the registered dialect (`sqlDialects`), never the generic `sql`. Params print compact, results indented and length-capped before highlighting, since shiki tokenizes whatever it is handed. Code folding does not come back with it: shiki is a tokenizer, folding is editor behaviour — there is no shiki API, transformer or plugin for it (`foldingStartMarker`/`foldingStopMarker` in `@shikijs/types` are inert TextMate grammar metadata), and an indentation-based reimplementation was written and reverted as ~90 lines of kit code standing in for an editor feature. The list/detail split is the one place a `ResizableHandle` keeps a resting hairline (`[&>div]:bg-border/50`) — inside a single pane there is no gutter to imply the seam. Open/close is the panel fold ([motion.md](motion.md)): the bottom panel of the vertical group inside the main pane, `preserve-pixel-size`, pinned to the stored `logger-height` px. A `motion.div` height animation with the px `ResizeHandle` was the interim after the first (unanimated) panel-group version; the `flex-grow` transition made the group viable again. The logger content is gated on having been opened once (render-phase state, not an effect) so its lazy chunk still waits for the first open while staying mounted at height 0 afterwards. Its list/detail split folds the same way: the detail panel stays mounted and latches the last inspected query so the pane does not empty mid-fold. The logger carries its own ✕ (the title-bar toggle stays as the way back in).
- Floating scroll-to-end control: `variant="outline"`, circle, lifts on hover — the shadow is the feedback; flat tint fills over text read as grime.
- **Boot shell**: `apps/app/src/shell.tsx` renders the chrome the window shows before the bundle compiles — one shell per router layout (`shell-auth` two-column frame, `shell-dashboard` centered column, `shell-connection` navigator gutter + rounded pane), all sharing a `ShellFrame` that draws the title bar. `Shells` renders the whole set, so adding a layout never touches the plugin. `src/boot.ts` picks one by adding the matching `shell-*` class to `<html>` — it also resolves the theme class and publishes `--shell-navigator-width`, and the plugin bundles it to an IIFE (`vite.build`, `write: false`) into the `<!--boot-->` marker, so it can import the leaf `lib/storage-keys.ts` that the seitu values also use — never retype a key or default in it. Bundling replaced a `boot.toString()` inline: that version broke the moment a lint autofix hoisted a helper to module scope, since the stringified function still referenced it and threw on the page with nothing to catch it. In dev the plugin also injects a `?direct` stylesheet link for `@tamery/ui/globals.css` — dev otherwise delivers CSS through the bundle, so every shell sits unstyled (and, once `[data-shell] { display: none }` finally applies, invisible) until React has already replaced them; `/create` deliberately reuses the dashboard shell, since an empty centered column is identical either way. Ids are per-shell and repeated hooks are data attributes (`data-shell-titlebar`, `data-shell-navigator`) — the frame renders once per shell, so an id there would duplicate. The `tamery:prerender-shell` plugin in `apps/app/vite.config.ts` renders both to static markup into the `<!--shell-->` marker in `index.html` — off the running server's SSR graph in dev, off a throwaway middleware-mode one in the build — so the markup is the React code and cannot drift; the head script picks one by adding `shell-app`/`shell-auth` to `<html>` from stored `last-location`, and `main.tsx` drops `[data-shell]` on the router's first `onResolved`. Keep both components hook-free and free of browser globals (they render in Node), and mirror the real chrome exactly — every class the shell shares with a live component comes from an exported const (`titleBarClassName`, `resourcePanelClassName`, `centeredPageClassName`), never a copy, which is why the swap is invisible. Per-user geometry the shell cannot know at build time comes from the head script instead — it reads `navigator-width`/`navigator-open` and sets `--shell-navigator-width`, which `[data-shell-navigator]` consumes, so a resized sidebar does not jump on swap. The chat and query-logger panes are in it too: the head script pulls the resource id out of `last-location`, reads that resource's seitu store for `chatOpened`/`loggerOpened`, and publishes `--shell-chat-width` (from `chat-width`) and `--shell-logger-height` (from `logger-height`); `.shell-navigator`/`.shell-chat`/`.shell-logger` gate the matching `data-shell-*` nodes, which are `box-content` plus the gutter padding so the var stays the panel's content size, exactly what the live panels persist. The script cannot use seitu to read them — `createWebStorageValue` plus its arktype schema bundles to ~155kB of render-blocking inline script against the current ~1.2kB — so it re-parses raw JSON and shares only keys and defaults with the seitu values. The visibility rules live **unlayered** in globals.css: inside `@layer base` a `display:none` loses to the `flex`/`grid` utility on the same element. Dev serves the same markup but cannot show the pre-JS paint: dev CSS arrives through the bundle, so the shell only styles once JS loads — check the real timing against a build. Auth content is not prerendered on purpose — the auth page animates itself in and a static copy would double-render.
- **Minimum window size**: `MIN_WINDOW_WIDTH` / `MIN_WINDOW_HEIGHT` in `@tamery/shared/constants` (900 × 600) are the one source — Electron's `BrowserWindow` clamps to them and `~/components/window-too-small.tsx` (mounted in `__root.tsx`, `z-100`, above dialogs and toasts) covers the app with an opaque `bg-body` kit `Empty` when the viewport drops below. Width is the connection layout's floor: navigator `SIDEBAR_MIN_WIDTH` 180 + a usable resource pane + chat `CHAT_MIN_WIDTH` 300 + the window's `p-2`. The overlay stays in the desktop build too — the native clamp does not cover browser zoom, and the web build has no clamp at all — and carries `[-webkit-app-region:drag]` so a too-small window is still movable while it is up. Detection is a module-level seitu `createMediaQuery` read with `useSubscription`, never a resize listener or a hand-rolled `matchMedia` store.
