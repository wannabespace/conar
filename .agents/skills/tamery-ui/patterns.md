# Native macOS patterns

- Window dimming: `.electron.window-blurred` swaps `--primary` to gray in globals — token-based chrome dims for free. No transition (AppKit snaps).
- `body` `overscroll-none`; inner scrollers keep native bounce.
- Context menus: always `AppContextMenu` (data-driven node tree; web renders base-ui, desktop pops native menu over IPC), never raw kit menu primitives. Destructive item last after a separator.
- **Open in New Window** is the first item of any row menu that stands for a route (navigator tables, connection cards), above a separator: the row's target must exist before the window opens (a table registers its tab first), then `openNewWindow` (`apps/app/src/lib/new-window.ts`) takes the route href — `window.open` on web, an Electron window on desktop. Secondary desktop windows open offset from the stored bounds and never restore maximized/fullscreen; landing exactly on top of the window you came from reads as nothing happened.
- **Control family** (kit): no border — `bg-input` + `shadow-xs` + hairline `ring ring-foreground/4`. **Disabled is `opacity-50` + no pointer events on the whole control**, and a composite control has to carry it on the surface the user sees: the combobox chips box reads the disabled state off its own input (`has-[input:disabled]:`) because the Base UI `Chips` part exposes no disabled attribute of its own, and without it a locked picker looks identical to a live one. Hover = `bg-accent`, the single hover surface between level 2 and level 3 ([colors.md](colors.md)), never a per-control mix. Border slot stays `border-transparent` (focus must not shift layout); **no `bg-clip-padding` on hairline-ringed controls** (opens a gap the width of the border slot). Floating panels take the same `ring ring-foreground/4` hairline, no borders, `shadow-xl` (`shadow-lg` reads as flat paper on light); menu/select/combobox shells `p-1`. **Focus = `focus-visible:focus-ring`** (kit `@utility` in `globals.css`: `ring-3 ring-ring/50`; `--ring` is `--primary`, so like AppKit it greys out with the window on blur). Matches a native focused field: one accent band outside the control, the control's own stroke unchanged — never `focus-visible:border-ring`, `outline-*`, or a per-site `ring-ring/N ring-N` pair; focus is always accent, never tinted by state. **Invalid = `aria-invalid:invalid-ring`** (the sibling `@utility`: `ring-3 ring-destructive/50`, declared after `focus-ring` so it wins while the field is focused). It is the same band at the same weight as focus, only red — a `border-destructive` tint underneath it adds a second edge and makes an invalid field read heavier than a focused one, so the kit carries none. A component dialing its own `ring-destructive/N ring-3` pair is the utility going stale.
- Popup radius: rows and search field `rounded-lg`, shell `rounded-xl`; kit density defaults — don't re-inflate or shrink. Menu rows (dropdown, context, menubar, select, combobox, command): `text-sm font-[450] tracking-wide` — 450 matches navigator rows and the tab bar (400 reads too light beside the chrome). Leading icons `size-4 text-foreground/70`, enforced kit-level (`/60` reads as watermarks beside near-black labels). Submenu-trigger chevrons are `size-3.5`, matching the breadcrumb separators — at the leading icons' `size-4` they read as buttons, not disclosure. Toolbar-button and tab glyphs keep `/60`. Separators `-mx-1.5 my-1`.
- **`PopoverContent` owns its padding through `padding`** (`default` 4, `sm` 2, `none`) — `none` also flattens the base-ui viewport slot, which is what a popover full of `Command` rows or an editor needs. A call site writing `p-0 **:data-[slot=popover-viewport]:p-0` is the prop going unused.
- **`CodeBlock surface="field"`** draws the field surface (`bg-input` + `rounded-xl` + `shadow-xs ring ring-foreground/4`) around a read-only block sitting in a form, so a page never hand-builds that wrapper; the default `none` leaves the block on whatever pane it sits on ([colors.md](colors.md)).
- **A `link` button owns `px-0`.** A link is text, so the variant drops the horizontal padding its `size` would otherwise give it — a call site writing `px-0!` is fighting the kit.
- Popovers size to content (`w-auto min-w-40`); dropdown and context menus do the same, capped `max-w-80` — only `Select` and `Combobox` match `--anchor-width`, because a menu row is usually longer than the trigger that opens it. `CommandInput` only at ~8+ items; hide a sole group heading.
- Grouped lists: one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`.
- **Editable value lists** are the kit `EditableList` (`custom/editable-list.tsx`), never a hand-rolled row stack: a call site passes `items` (`{ id, value }`), `onItemsChange` and the wording (`addLabel`, `placeholder`), plus `canRemoveItem` where some rows are fixed. The list holds itself to one row (the remove control is gone on the last one) and marks repeated values `aria-invalid`, so a call site seeds at least one row and never has to ask for either. It owns the whole keyboard and pointer contract so every list in the app answers the same keys: Enter inserts a row below the caret and focuses it, Backspace on an empty row removes it and lands the caret at the end of the one above, ↑/↓ walk rows, ⌥↑/⌥↓ move the row itself, Escape blurs back to the surface (the first rung of the Escape ladder), a multi-line paste fills the row it landed in and spills the rest below, and a grip in the row's leading addon drags to reorder (`Reorder`, handle-only so the input keeps the pointer). A drag holds its order locally and reports it once on release, not on every crossover — the call site sees one change, so a form that derives anything from the order (the enum form's in-place-or-recreate plan, and the note it prints) does not flicker through a dozen readings while the pointer is still down. Moving a row by keyboard re-focuses it — React reorders the keyed node, which blurs the input. The list owns focus rather than the rows: ↑/↓ focus the neighbour outright, and anything that rewrites `items` parks the row's id in a ref that a layout effect consumes on the next render, so the request is spent once and the same row can ask again. Rows are transparent over the list's one surface, so a dragged row takes its own `bg-input` + `rounded-xl` + `shadow-lg` + `z-10` for the length of the gesture — without a fill it slides across its neighbours and both rows' text shows through each other. Ids belong to the call site — a row seeded from existing data can carry its own identity (the enum form keys originals by their index to tell a rename from a removal) while the list mints a uuid for rows it adds. It paints one field surface (`bg-input` + `rounded-xl` + `shadow-xs ring ring-foreground/4`) holding `divide-y` rows of `InputGroup variant="flat"` — the flat variant drops the pill's surface but keeps the input's own height, padding and focus ring (rounded at the list's first and last row), so the list reads as one field rather than a stack of floating inputs. The inputs stay in the body font — an editable list is a form, and mono type on rows of short identifiers reads as a code block the user cannot type into. Adding a value is an `outline` `size="sm"` button (a tier below the card's `h-8` rows — at `h-8` it reads as a loose fourth row) **under the card**, not a row inside it: the card holds only values, so what it shows is what the object is, and the control that changes it sits outside on its own line (`gap-2`), with the list-level `FieldError` beside it. An add row inside the card reads as one more value at a glance — a list of three values and a fourth row the user has to read to know it is a button — and its hairline makes the card's last edge belong to a control rather than to the data.
- Divider between chrome-strip control groups: kit `<Separator orientation="vertical" className="mx-0.5 h-4!" />`, never a hand-rolled `bg-border w-px` span (kit vertical defaults to `h-full`; the `!` is explained in [gotchas.md](gotchas.md)).
- **32px chrome strips** (tab bar, chat header, logger header): buttons `size="icon-xs"` (glyphs auto-size to 3.5 — never add `size-*` to the icon) — `icon-sm` fills the strip and its hover square reads as a slab, even beside full-height tabs. Anything full-height inside the strip sizes to the header's *content* box: `h-full`, never a literal `h-8` (spills 1px over the `border-b`). End cells `px-1`.
- **Tab strip**: Finder-style — content-width tabs, active tab = raised notch; type shows via leading icon only, no per-type color/badge. Labels disambiguate only when needed (schema prefix at 2+ open schemas; query ordinal from the second instance). Trailing cell (`+` menu, chat latch) pinned to the bar's far right edge. Contextual controls stay mounted and go `disabled`, never unmount. **A control in the window chrome must not repeat inside the page it acts on** (refresh: SKILL rule 10). Active state is carried by surface and text colour only — every tab keeps `font-[450]`; a weight bump on the active tab re-measures its label and the tab jumps wider.
- **Pane-edge tab strips** (logger detail): `TabsList variant="bar"` — flat full-height cells on `bg-body/50` (same `text-sm px-3` as the window tab bar — a smaller `text-xs px-2.5` step was tried and reverted), active cell `bg-background` with no shadow or side borders, so it reads as a notch in the pane edge rather than a segmented pill.
- Tab rename: double-click (promotes preview first); the tab must not resize entering edit mode — unstyled `field-sizing-content` input inside the same container classes. Empty or equal-to-derived clears the override.
- Navigator sections pad `pl-2` only; their right inset is the pane's own gutter (`pr-1.5`, see pane splits).
- **Sidebar holds no action icons** — **an action belongs to the surface it changes, not the surface you were looking at.** New tab → tab strip's `+` dropdown; window-spanning toggles → title bar. Footer = labeled rows, never icon buttons (a footer is a menu, not a toolbar). **A menu with a single item is just a button with an extra click.**
- Tables ↔ Schema switcher: one morphing row above search; which list shows is session state, **never persisted** (reload lands on Tables). Second list is named **Schema** — the umbrella must cover the visualizer too. List rows use muted icons, not primary (distinct glyphs in blue read as noise).
- **A trigger that opens a menu takes no tooltip** — the menu names its own items; either a button acts or it opens a menu, never `+` plus caret.
- **Command popups** (sort popover): active state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row; no nested ghost buttons except the remove ✕). **A hover-only ✕ is never the only way out.** A nested trailing control `stopPropagation`s on both `onPointerDown` and `onClick` (cmdk selects on click) and sits absolutely inside the row, never as a flex sibling. A two-state control in a row is one flipping icon, not a pill with both states; a picker belongs in the same popover's body, never a child popover. Every `Command` child lands on the same 4px left edge — the root has no padding, each section carries its own `p-1`.
- **Table toolbar counters**: outline Buttons sharing one shape, each count on the control that acts on it. **Count always visible, geometry always stable** — no morphing, no popping badges; a `Skeleton` bar before the count is known (a premature `0` is a wrong answer). Numbers roll via the kit `NumberFlow` wrapper only (stock timings read slow-motion); the changing number is the `value`, the stable part the `suffix`. Tooltip anchors on the button itself. Spent state = `disabled` + `disabled:opacity-100`, never a span swap (geometry must not change). Invalidate by query-key prefix — never thread state around to reconstruct a key.
- Alerts: `variant` carries the tint (a tinted fill over the plain `bg-card` default — a card-coloured alert reads flat on a pane); there is one density, pane scale, because an alert always sits inside a pane, form or dialog and a second larger size only ever shouted. A call site passing its own padding, radius, text size or tint is a missing variant, not a page override. **An `Alert` reports what already happened — a failure the database raised, a job that finished. What a pending action will do belongs on the action, never in a box above it.** "Saving drops and rebuilds this" is the submit button turning `warning` (`destructive` when the action destroys data), relabelled to the real verb — `Rebuild index`, `Replace enum` — with the consequence in its tooltip; no alert, and no confirmation dialog in front of it, because a modal restating a warning the button already carries is a second click for a sentence the user has read. A confirmation dialog is only for an action with no undo and no draft to back out of — dropping an object, deleting rows. "This field is locked because the shape lives elsewhere" stays a `FieldDescription`: nothing is about to happen, and a tinted box for it turns every form into a wall of notices, which costs the real warning its weight. Keep the sentence to what the user can act on — the consequence, not the engine's reason for it.
- Empty states: kit `Empty` primitives; a pane-level empty state is `~/components/pane-empty.tsx` (icon + title + one line, nothing else — the pane density lives there, so no call site re-dials `Empty`'s padding or type scale) — **anything added competes with the emptiness, and the emptiness is the message.**
- **Icons:** Hugeicons — `iconLibrary: "hugeicons"` in `packages/ui/components.json`. Render with `HugeiconsIcon` from `@hugeicons/react` and icon data from `@hugeicons/core-free-icons`; `strokeWidth={2}` matches the shadcn generator. Never mix another icon set. A glyph that flips with state is one `HugeiconsIcon` with a ternary on `icon`, never two branches differing only by the glyph.
- Shortcuts: kit `shortcuts.tsx` only; **a key is a Hugeicons glyph, never the unicode character**; passive hint lines take the bare glyph, not a `Kbd`; only advertise shortcuts that fire (gate Electron-only on `window.electron`).
- Tooltips: never nest triggers; `TooltipContent` is `inline-flex` — wrap multi-line content in a flex column, and prose built from several nodes (a masked name plus a sentence) in **one** block child, or each node becomes its own flex item and the sentence lays out as a second column beside the name.
- Global banner (`global-banner.tsx`): slow and broken connections report here — a page that only spins is the bug. Slow banner shows live elapsed seconds; the reconnect banner suppresses it; wording is about the response, never "connecting".
- Toasts: `unstyled: true` + glass recipe, never sonner's default theme. **The `Toaster` portals to `document.body`** — `#root` carries `isolate z-10` (`index.html`), so anything React renders inside it is trapped in that stacking context and paints under the overlays base-ui portals to the body at `z-50`, however large sonner's own z-index is. The portal escapes it; the list is pinned to `z-60`, one tier above overlays and below the `z-100` window-too-small cover.
- Interactive icons app-wide: ghost hover surface + muted→foreground icon + tooltip; latched `bg-foreground/10 text-foreground` ([colors.md](colors.md)). Upgrade bare icons whenever touching a file.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics); imperative press-nav via `pressNavProps`.
- **Filter field**: suggestion order is JSX order (`shouldFilter={false}`) — the literal answer first, `Ask AI` last. Chips scroll in a capped row (the field must not grow forever). AI results report inline as a pinned header above the list — never a toast, never inside the scrolling list. Quota exhaustion disables only the `Ask AI` item, never the input. Blur keeps the in-progress stage; only Escape steps back. Chips read in prose (`Is not null`), never raw SQL.
- Dither shader: **auth layout only** — an animated background never sits under a card, and each instance is a WebGL context. `dither-in` entrance is the only other carrier — **dithering governs entrances, never resting chrome** (grain on resting surfaces reads as the transparency checkerboard / dirt).
- Title-bar switchers: the workspace menu lists workspaces only — a flat row per workspace, check on the active one; connections and resources are reached through the breadcrumb dropdowns beside it, never nested under a workspace row (one menu, one axis). Subscription-gated actions render enabled and route to the upsell modal — the modal is the gate, not a greyed item.
- Data table: ghost cell controls only (outline buttons down a column fight the values); **no vertical rules, header included** (zebra + hover = macOS list; rules = spreadsheet). Skeleton bars (table, navigator) deterministic via `pseudoRandom` (`@tamery/shared/utils/helpers`) seeded by index, never `Math.random`.
- **Visualizer loading** is a canvas skeleton, not a logo spinner: the dotted background, the top-right search + schema controls, and ghost table cards at the real node geometry (`w-66`, header row, column rows). **Nothing about it varies** — identical cards, evenly spaced and centred, one width per bar role (name, type), one shared pulse. The data table earns ragged `pseudoRandom` widths and staggered delays because a wall of identical bars across 20 rows reads as a rendering bug; a few cards floating on open canvas have nowhere to hide the noise, so jittered widths, scattered positions, uneven column counts and depth fades all read as debris rather than tables. Ref: `visualizer/visualizer-skeleton.tsx`.
- Markdown: kit `Response` only; the chat does **not** pass `streaming` (per-block memoization restarts the word fade every block). Fenced code = `ResponseCodeBlock` (lives in `response.tsx`: language header, copy, 10-line peek over the bare kit `CodeBlock`) via `components={{ code }}`; inline code is the same override's other branch. Chat tool parts print their JSON through the same `ResponseCodeBlock`. Anthropic hands back signature-only reasoning parts (`text: ''`, a `providerMetadata.anthropic.signature` and nothing to read), so a reasoning part with no text renders nothing — an empty `Reasoning` disclosure otherwise sits above every answer.
- **Pane splits**: navigator, chat and query logger are `ResizableGroup`/`ResizablePanel`/`ResizableSeparator` from `@tamery/ui/components/custom/resizable`, a styled `data-slot` wrapper over the unstyled `Group`/`Panel`/`Separator` mechanics in `motion-panels` (an external npm package, framework-agnostic core plus a React adapter, motion, no third-party layout library) — the mechanics stay out of the kit because the kit is the shadcn registry, but every className lives in the wrapper, which the kit's own `@source` glob already scans; logger detail stays plain flex at a percentage. A group is a flex row or column; sized panes take `size` as a pixel number (`256`) with `minSize`/`maxSize`/`defaultSize` in px too, exactly one pane per group has no `size` and fills the rest. State is controlled: `size`/`onSizeChange` (fires on drag release, keyboard steps and double-click, never per frame) and `collapsed`/`onCollapsedChange` (a drag past half of `minSize` closes the pane) — the route keeps them in seitu values (`navigator-width`, `chat-width`, `logger-height`, bounds in `lib/constants.ts`), so persistence is the callback itself. A width is a habit, not a property of the database, so it is global, not per resource — the runner's results split is the exception: its height sits beside `resultsVisible` in the per-tab runner store (`layout`, bounds still in `lib/constants.ts`), because that pane's open state is already per tab. **The separator is a sibling between the panes** (`<ResizableSeparator aria-label="Resize navigator" />`, same shape as react-resizable-panels) and optional: a sized pane is always draggable by its edge, the separator adds the visible grip, keyboard and double-click. It takes no flow space — a zero-width slot at the seam whose grip hangs over the sized pane's own gutter (navigator `pr-1.5`, chat `pl-1.5`, logger `pt-1.5`) — no negative margins, nothing to disable. It takes no side: the package detects which sized pane it sits beside and which edge of that pane faces the fill pane, and puts the grip, the content anchor and the drag direction there, so a pane before the fill grows to the right/down and one after it grows to the left/up. It is a focusable `role="separator"`: arrows step 10px (Shift or PageUp/PageDown 50), Home/End jump to the bounds, Enter toggles collapse, Escape cancels a drag in flight, double-click resets to `defaultSize`. Styling: a transparent grab strip around a 2px line that fades from `--primary` at its centre to transparent at both ends (an eclipse, `bg-linear-to-r`/`-to-b` picked off the group's `aria-orientation`), so the seam reads brightest where the pointer grabs it and never ends in a hard stub against the pane corners. The colour is fixed; only opacity moves — `opacity-0` at rest, `40` on hover and focus, `100` while dragging (a gradient stop is a CSS variable and does not transition, so the fade rides `transition-opacity`). CSS `:active` holds through a captured pointer drag, so that is `group-active/resizable-separator:`, not a state prop — no permanent grip. Open/close, drags and every size change animate on the house curve by default ([motion.md](motion.md)); a pane's `transition` prop (motion `Transition`; `{ duration: 0 }` snaps) overrides the timing. The px-driven kit `ResizeHandle` survives for table column resizing alone. Where two splits meet there is no extra component (matching react-resizable-panels): a press within 5px of another separator's grip drags that one too, each resizing its own pane, under a `move` cursor — the navigator seam meets the logger seam, and the chat seam meets it from the other side. Hover feedback is shared, never per-grip: at a crossing every separator that press would drag takes `data-crossing` (kit styles it like `:hover`), and from pointerdown until release they take `data-resizing` (styled like `:active`, before the drag threshold too — `:active` alone would light only the grabbed grip) — one grip lighting alone while two move reads as broken.
- **Chat panel**: its header is the chat's share of the window's top row — same `h-8` as the tab bar beside it, same muted ghost icon buttons, so both strips read as one line. Width persists globally (`chat-width`, pane splits above); the open chat id is its own `sessionStorage` value, not part of the resource store — per window, so a second window of the same connection opens its own chat instead of following the first. Toggle in the tab bar's trailing cell (a per-resource control sits under the pane it opens); ⌘L lives with the button, not the panel. Without a subscription the toggle (and ⌘L) opens the upsell modal instead of the pane — the button stays enabled, the modal is the gate; while the subscription query is still pending the pane opens as usual. Open/close is the pane fold ([motion.md](motion.md)); the chat mounts on open and unmounts once the exit slide ends, so nothing runs behind a closed pane. Composer textarea owns the whole box with the send control floating over it (an addon row leaves the box's bottom unclickable). Assistant turns render **every** part (text-only join silently loses tool work); user = bubble, assistant = bare `Response` (bubbling both halves the reading width). First-token wait = `Spinner` inside the last turn's item — never a skeleton (length unknown), never its own item (anchor-pass trap, [gotchas.md](gotchas.md)). No `scrollAnchor` anywhere — provider `autoScroll` alone, so every window holds the bottom and a chat open in two of them reads the same ([gotchas.md](gotchas.md)). Spinner tracks the request, not the transcript — `'submitted' || 'streaming'`, the same pair that arms the stop button (the resume probe's `submitted` counts; it is a real round-trip). Never "the last turn is unanswered": a turn stopped or failed before its first chunk persists nothing, so that reading strands the spinner under the question for good. Switching/new chat aborts nothing — streams detach server-side; the stop button is the only abort. Title falls back to the first user message before `New Chat` (server-generated title syncs late). Live exchange = `useChat`; settled turns = collections merged by id, persisted wins (`api.md`). Stream failures report inline above the composer as one kit `Alert variant="destructive"` — message in the description, `Retry` in `AlertAction`, no title, no upsell branch, never truncated and never a toast (the chat's own procedures are silenced in the global oRPC error interceptor; session expiry still toasts and signs out). Chats collections are not awaited in `_protected`'s `beforeLoad`, so the chat reads them with `useLiveSuspenseQuery` under `<Suspense fallback={<ChatSkeleton />}>` — never `useLiveQuery` plus a hand-rolled `isReady` gate (zero rows is ambiguous until sync lands; suspending computes the `resume` decision from real rows).
- **Query logger**: a log list, not a card list — full-bleed `h-7` `Item` rows (`border-0`, [gotchas.md](gotchas.md)), no hairlines, `hover:bg-accent`, selection `bg-foreground/10` (the latched-control tint — hover and selection must differ). Not here: Finder-style solid `bg-primary` rows (a slab when full-bleed, and `primary-foreground` text kills the token colours), zebra, `hover:bg-popover` ([colors.md](colors.md)), a primary edge bar, per-status counter chips in the header. Status is a `size-1.5` dot coloured only for error/pending — success stays `bg-foreground/20`, a column of green competes with the highlighted SQL. Row SQL renders through kit `CodeInline` (shares `CodeBlock`'s highlighter; keep `data-slot="code-block"` for the dark-theme rule); rows are virtualized. Header = title + clear + close; the title-bar toggle (⌘J, registered beside that button like chat's ⌘L) is the way back in. Inspecting a row opens a **detail pane beside the list**, never a viewport-wide popover. Detail = in-flow `TabsList variant="bar"` (Query / Error / Values / Result · N) over one bare kit `CodeBlock lineNumbers` (a `pre` — highlight and line numbers only; header, copy and peek belong to chat's `ResponseCodeBlock`) for the active tab only ([gotchas.md](gotchas.md): base-ui exit stall), copy as glass floating chrome top-right inside the panel, `no-scrollbar scroll-fade` on the scroller, no ✕ — re-clicking the row closes it. No second strip (buttons pile up in one corner); no `variant="line"` (its underline floats a second line above the header border). The `Tabs` root wraps the whole logger, so the active tab is state keyed to the shown query id and reset in render — never a `key` on the root, which holds the virtualized list. Read-only Monaco was tried twice for the bodies and reverted to shiki both times — an editor instance for a viewer; shiki's `sql` grammar dropping the odd keyword (`OFFSET`) is accepted. No folding: shiki cannot, and an indentation reimplementation was ~90 kit lines standing in for an editor feature. Line numbers come from `CodeBlock`'s `lineNumbers` prop as a CSS counter on each line's `::before` (shiki's own recipe) — nothing in the text flow, so selection and copy are code-only without `select-none`. Params and results print indented, one value per line, length-capped before highlighting. The list/detail seam is a hairline border on the detail pane instead of a gutter — inside one pane an empty gutter reads as rows stopping short. Open/close is the pane fold ([motion.md](motion.md)) at the persisted `logger-height`; the lazy chunk loads under `Suspense` (skeleton) during the first slide-in, and the logger unmounts once the exit slide ends. The detail pane sits at width 0 when no row is selected and 55% when one is, driven straight off `selected` — nothing mirrors the layout in state. A version with the split always open was tried and reverted (an empty pane sitting at 40% reads as broken).
- **Code dialog** (table toolbar → Code): one modal, no sidebar — `Dialog variant="panel"`, the kit's full-bleed dialog surface (no padding, flex column, wider and fixed-height, and it drops the title to pane density through the dialog's context), so the call site writes no padding, gap or max-width of its own. A `h-12` title row (masked table name left, Schema/Query segmented `Tabs` centred in a `grid-cols-[1fr_auto_1fr]`, `DialogCloseButton` right — the kit's own ✕, so `showCloseButton={false}` moves it onto the row's centre line instead of the popup corner) sits over the query-logger detail recipe: formats as a `TabsList variant="bar"` with the copy button in its trailing cell, one bare kit `CodeBlock lineNumbers` below, `no-scrollbar scroll-fade`. The block takes `size="xs"` and `wrap` — a modal exists to read code, the logger's `text-2xs` is pane density; `wrap` hangs the indent by the width of the kit's own line-number column (a masked scroller hides its horizontal scrollbar, so an overflowing line would just be cut, and the number-column width belongs beside the CSS that draws it, never re-measured at a call site). Formats absent for a dialect are hidden, not disabled (`generators/compatibility.ts`). No Monaco: a viewer, not an editor ([gotchas.md](gotchas.md)).
- **Seed panel** (`table/-components/toolbar/actions/actions-seed.tsx`): a right-side `Drawer size="sm"` (`swipeDirection="right"`, `sm:[--drawer-content-width:38rem]!` — the kit's `sm:data-[swipe-axis=x]` width wins without the `!`). **`size="sm"` is the drawer's pane density**, carried to header, title, description and footer through the drawer's context: the default header is a `p-4` block with a 16px title that dwarfs the 36px chrome rows under it, and the default footer stacks its buttons in a column; `sm` gives a two-line header at `px-3 py-2` with a hairline under it and a single footer row above one; the ✕ comes from `DrawerHeader showCloseButton` (the kit's own `DrawerCloseButton`, centred on the two lines, reserving its own right gutter) — a drawer with a Cancel button in the footer still needs the corner ✕ every other window has, never a centered dialog, and **never a form of per-column dropdowns** (two versions of that were built and thrown out: a column of outline triggers reads as a settings form, and a popup per row hides the choice). A `9rem` left rail was tried and dropped: the fields were squeezed to make room for prose that read as loud as they did, and a section with little to say (the read-only SQL) left the rail empty for its whole height. **Schema is a field of the form, not only the list's filter** — a section whose objects live in a schema opens its General section with a `SchemaField` (`-components/schema-select.tsx`, hidden when the database has one schema), seeded from the list's schema select and locked once the object exists, since no engine here moves an object between schemas with an `ALTER`; changing it clears the table and column pickers under it, because those options come from `tablesOf(schema)` and the columns query keyed on it. Creating into another schema by first re-filtering the list behind you is the bug: the form states where the object will land, so it also owns the choice. Sections are General (name, then the one choice that reshapes the object) · the object's target (table, columns) · its options · `InspectorDefinition` (the read-only SQL of an existing object) — and every field that has a rule worth knowing carries its own `FieldDescription` under it, including the dialect notes about what a save will actually run. **Every inspector form is a `useAppForm`** (`@tamery/ui/components/tanstack-form`), never a row of `useState`s: `defaultValues` comes from the section's `draftOf(item, schema)`, the whole draft is read back with `useStore(form.store, (state) => state.values)` and handed to the section's pure `<object>State(...)` for everything derived (title, locks, dirty, warning), and every control sits inside a `form.AppField` so its `id`, the label's `htmlFor`, `aria-invalid` and the error line all come from the field name — a control that hardcodes an `id` beside a `field.Label` points the label at nothing. Validation is one `<object>Errors(draft)` function wired as the form's `onChange` **and** `onMount` validator, so a form that opens invalid already knows it. **Save is disabled by "nothing changed", never by "not valid"**: a greyed-out button explains nothing, so an incomplete form still submits, `handleSubmit` marks every field touched, and the missing pieces say so. **A form with no object behind it has always changed** — every `changed` predicate is `item ? … : true`, because a create form compared against an empty draft reads as untouched and disables the one button the user came for. **What a `changed` predicate compares against is the draft the form opened with (`draftOf(item)`), never the row** — the seed normalizes (a foreign key's schema falls back to the constraint's own), so a diff that re-derives its own fallbacks disagrees with it and reports an untouched form as edited, which both enables save and arms the destructive `warning` label on a form nobody has typed in. Submitting owns the trip to the problem: `InspectorFooter` takes the `form` itself, not an `onSave` closure, and after `handleSubmit` focuses the first field whose meta is invalid (`id` is the field name, so `#name` finds it), which scrolls it into view — a mark on a field the user cannot see is the same dead end as the disabled button. **A field error never takes vertical space, and the mark sits on the control that is wrong**: `field.Input` wraps its `Input` in an `InputGroup` and renders the kit `FieldError` in an `inline-end` addon — a destructive `AlertCircleIcon` inside the field at its right edge, the message in its tooltip and in `sr-only` for `aria-describedby`. Nothing is inserted into the column, so a form that turns invalid does not push every field under it down, which is what made validation read as the form jumping. **Every control that owns a box hosts the mark inside that box** — one error UI for the whole form, because a mark beside the label on one field and inside the box on the next reads as two different kinds of problem. The field publishes the mark through `FieldInvalidProvider` (`field.tsx`) and every control with room for it (`SelectTrigger`, `ComboboxChips`) reads it with `useFieldInvalidMark` and derives its own `aria-invalid` from it, so a select and a chips picker ring and mark exactly like an input while no call site wires either; `field.Textarea` is the textarea's way in, since a `textarea` element has no children and needs the `InputGroup` to hold the addon. Only a control with no box of its own falls back to a mark beside its label: `field.Label` renders a `FieldError` too, hidden whenever the field's own control already carries one, so the two never both appear. A list of controls marks whatever is actually wrong, at that scale: `EditableList` takes the field's message (`fieldErrorMessage(field)`) and splits it — a duplicate is one row's fault, so that row alone rings and carries the mark in its own `inline-end` addon beside the remove button (which fades in on hover or focus-within and holds its space while hidden — a column of ✕ on every row reads as the list's main offer, and keyboard reach is what `focus-within` keeps); anything else the caller rejects (nothing filled in yet) belongs to the list, so the box rings once and states itself once, beside the `Add value` button under it. Repeating the mark on every row for a single list-level complaint reads as several separate faults, and a mark on the section header reads as the *section* being wrong and points at nothing the user can fix. `field.PasswordInput` does the same through `PasswordInput`'s `addon` slot, so the mark lands beside the reveal eye rather than vanishing. A call site writes no `<field.Error />` at all; a field with neither an input nor a label (the Monaco editor) hands one to its `InspectorSection`'s `action` slot. **The `<form>` element is the kit's `Form`** (`@tamery/ui/components/tanstack-form`, `<Form form={form}>`) — it owns `noValidate` and the preventDefault/`handleSubmit` wiring, so no page hand-rolls either; a raw `<form>` lets the browser's own validation bubbles fire first and preempt the form's messages entirely. **Validate `onChange`, never `onSubmit` alone**: an `onSubmit`-only validator leaves the form invalid after the first failed press, so the next press is refused before validation re-runs and every mark silently disappears. `onChange` also clears each mark the moment the user fixes that field. Submit buttons gate on `isSubmitting`, never on validity. **The mark does not animate in** — it is a state, not an arrival, and a fade on something that appears while the user is typing reads as lag. Schema is a field of the draft like any other, so clearing the table and column pickers under it is the same `form.setFieldValue` every other field uses — **with `{ dontUpdateMeta: true }`, because TanStack Form marks a field touched on every `setFieldValue`**, and a cascade reset that touches the pickers makes them show "Pick at least one column" for a choice the user has not made yet. `onSubmit` fires the section's `useDefinitionMutation` with `mutate`, not `mutateAsync` — the mutation still owns invalidation, the toast and the inline `error`, and nothing rejects into the form.
