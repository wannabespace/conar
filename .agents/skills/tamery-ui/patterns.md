# Native macOS patterns

Paths under `apps/app/src/routes/_protected/connection/$resourceId/` are written relative to it.

- **Window dimming**: `.electron.window-blurred` on `<html>` (`electron` class set in `index.html`, `window-blurred` toggled by `use-window-focus-observer.ts`) swaps `--primary` to gray in globals — accent chrome dims for free if it uses these tokens. No transition (AppKit snaps).
- **No root rubber-band**: `body` has `overscroll-none`; inner scrollers keep native bounce.
- **Context menus** — all go through `AppContextMenu` (`apps/app/src/components/app-context-menu.tsx`), a data-driven `AppMenuNode[]` tree, NOT the raw `@tamery/ui` kit primitives. Web renders the base-ui kit; desktop pops the OS-native menu over IPC (`window.electron.menu.popup`, main-side `Menu.buildFromTemplate`). Web-only node fields: `icon`, `shortcut`, `trailing`, `className`, destructive-red `variant`. Native-only: `accelerator` (display hint), `nativeLabel` (fold trailing info into text since native has no trailing slot), `checked` (checkbox checkmark — used for active header-cell sort). `contentProps` (`side`/`align`/`className`) and `render` (merge into an existing element, e.g. header cell div) are web-only; native ignores them. Controlled sites pass `open`/`onOpenChange` (native drives them imperatively around the popup). Destructive item last after a separator. Right-click on rows/tabs/table column headers/cells/connection cards; the old chevron dropdown was rejected. Open state styled via `data-popup-open:bg-accent` (base-ui sets it on web; the wrapper sets it on desktop while the native menu is open).
- **Control family** (outline Button, SelectTrigger, Input, InputGroup — kit level; h-6 chips use `shadow-2xs`): **no border; definition comes from `bg-input` + `shadow-xs` + half-pixel hairline `ring-[0.5px] ring-foreground/4`**, hover/open/expanded use the **foreground-mix**: `bg-[color-mix(in_oklch,var(--input),var(--foreground)_3%)]` for filled controls, `bg-foreground/5` for ghost — foreground flips per theme, so hover darkens slightly in light and lightens in dark from one construction (accent-based and lighten-only hovers were rejected). Focus states override the ring slot (`focus-visible:ring-3 ring-ring/30`), returning to the hairline on blur. Border slot stays as `border-transparent` so the focus ring doesn't shift layout — **no `bg-clip-padding` on hairline-ringed controls**: clipping leaves a 1px gap between bg and ring that makes the ring float visibly (bit us in dark mode); bg must extend under the transparent border so the ring hugs it. Floating panels use `shadow-lg ring-1 ring-foreground/4` instead of borders; structural panes/cards keep their hairline `border`. Sizes only via props (`size="sm"` → h-7 rounded-lg, default → h-8 rounded-xl) — never per-page `h-*` overrides. Selects stay `font-normal`, buttons `font-medium`.
- **Menus compact**: kit defaults (`min-h-7 py-1 text-sm`, `rounded-xl`) — don't re-inflate or shrink.
- **Menu item icons stay dimmed**: leading icons in dropdown/context/menubar items are `text-muted-foreground` — the label carries the item, the icon only anchors it. Enforce kit-level on the item (`*:[svg]:text-muted-foreground`, destructive/checked variants keep their own color), never per-instance `className="text-muted-foreground"` on every icon. Submenu chevrons and trailing `CommandShortcut`/accelerators are muted too.
- **Popovers size to content**: `w-auto min-w-40`; `CommandInput` only at ~8+ items; hide group headings when one group.
- **Grouped lists** (dashboard): one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`. Sections (labels/types): micro-label header per section, one container each, ungrouped last.
- **Tab strip** (`-components/tab-bar.tsx`): Finder-style — content-width tabs, no truncate, each `border-r border-b`, active `border-b-transparent bg-background`, bar `bg-body/50`, and the trailing filler `div` keeps `border-b` running to the edge so the active tab reads as a raised notch. One strip holds every view type; type shows only through the leading icon (`TAB_ICONS`, `size-3.5`, muted → `text-primary` when active) and the label — no per-type color, badge, or border. Labels disambiguate only when they must: table tabs drop the schema prefix unless two schemas are open, and the one multi-instance type (SQL runner) gets a trailing ordinal from the second one onward — never "SQL Runner 1" when there is one. Every other type is a singleton, so re-triggering focuses the existing tab. Preview italics are table-only. Leading toolbar (sidebar toggle, history nav, contextual refresh) sits in its own `border-r border-b` cell before the strip, and the trailing `+` cell mirrors it after. The last tab drops its `border-r` (`isLast` prop, not a CSS `last:` selector — the `Reorder.Item` wrapper swallows that) so the pinned cell's `border-l` is the only divider when you scroll to the end. Contextual controls in that toolbar stay mounted and go `disabled` when they don't apply (refresh on a non-table tab) — unmounting them makes the toolbar reflow every time you switch tab type.
- **Tab rename** (same file): **double-click renames** (it promotes a preview tab first, so the old promote-on-double-click still happens). The tab swaps its `<span>` for a bare `<input>` inside the same chrome, and the button element becomes a `div` for the duration — an input inside a button is invalid and fights press-nav. **The tab must not resize when it flips into edit mode**: the editing container keeps the button's exact classes (same `pr-8`) and the input is fully unstyled — `field-sizing-content min-w-4 border-none bg-transparent p-0 outline-hidden`, inheriting font, italic, and color. Any padding/border/ring shifts the text's start position and the tab visibly jumps under the cursor. Autofocus + select-all, Enter/blur commits, Escape cancels; an empty value or one equal to the derived label clears the override instead of storing it. Reorder drag is disabled while editing. Context menu carries `Rename`, plus `Reset Name` only when an override exists.
- **Sidebar holds no action icons** (`-components/navigator/`): the navigator once accumulated six buttons across two rows (new runner, visualizer, logger, open-in-web, system tables, refresh) and read as a control panel. Each moved to where its effect lives — the general rule: **an action belongs to the surface it changes, not to the surface you happened to be looking at.** New SQL Runner → a `+` icon button in a cell pinned after the tab strip (`border-l border-b px-1`, ghost `icon-sm`, "New query" tooltip), **outside** the scroller so it survives any number of tabs. Shapes tried and dropped along the way: a labeled `＋ New query` cell (too wide for chrome that repeats), an outline button at the top of the sidebar, and an icon button beside the list switcher — creating a tab reads best where tabs live. Query logger → the app title bar's trailing cluster (`_protected/-components/protected-titlebar.tsx`), beside the command palette, rendered only when a `resourceId` is in the route and latched `bg-foreground/10 text-primary` — it toggles a panel that spans the whole window, so it belongs to window chrome, not to the sidebar. Open-in-web → a globe icon button beside the search field (`navigator-menu.tsx`), rendered only on desktop for cloud non-localhost connections; it was a `⋯` overflow menu until the system-tables toggle was deleted and one item was left — **a menu with a single item is just a button with an extra click**. Show-system-tables lost its UI but kept its plumbing: `connectionResourceStore.showSystem` still feeds `resourceTablesAndSchemasQueryOptions` (and its query key) from every call site, defaulting to `false`, waiting on a settings page. Deleting the toggle is a UI change; deleting the parameter would have been a data change, and those are worth separating. What remains visible in the sidebar: switcher, search, refresh, and (on desktop) the globe. Consequence: hiding the navigator (⌘B) no longer hides any action — that was the old layout's real cost.
- **Sidebar list switcher** (`navigator/navigator-switcher.tsx`, `navigator/definitions-section.tsx`): the sidebar body swaps between the **Tables** list and the **Schema** list, driven by **one morphing row** at the top of the sidebar, above the search field — a full-width `h-7 rounded-md` ghost Button showing `⧉ Schema ›` from the tables side and `‹ Tables` from the other. Same control in both states: label and icons crossfade with a 6px slide in the push direction (`AnimatePresence mode="popLayout"`, 150ms house curve) so push and back read as one object moving. The body swap animates `opacity` + 12px `x`, 180ms. Which list is showing is **session state, never persisted** (in-memory `getNavigatorStore`) — a reload always lands on Tables, because coming back to an app parked in a secondary view reads as the app losing your place. Whichever element leads the sidebar takes `pt-0.5`, not `pt-2`: the sidebar shares the page's `m-2` with the content pane, so a second full step of top padding starts the column 8px below the pane beside it. The resize handle is a `w-px` bar inside a `px-2` wrapper — hairline visual, 17px grab target. The column's right padding (`pr-2.5`) is derived from that, not picked: the bar sits 8px off the pane, so the rows need `bar offset − their own px-2` to leave the same gap on their side. Re-derive it whenever the bar's width changes, or the sidebar's contents end up visibly closer to the divider than the pane is.
- **Naming the second list**: it is **Schema**, not "Definitions", because the visualizer lives in it (first group `Overview`, then Structure / Types / Logic / Security). Once a diagram view needs a home, the umbrella has to cover views as well as objects. General rule: **a growing pile of footer rows means the second list needs a broader name, not more footer.** Its rows are the standard `SidebarMenuButton` (h-7, `rounded-md`, solid `bg-primary` active, single click = preview tab, double = promote) with **muted icons, not `text-primary/75`** — a handful of distinct glyphs in blue reads as noise, while the tables tree repeats one glyph so its blue reads as texture. It carries its own filter field (same `bg-input/60 h-7` InputGroup as the tables search) and groups rows under `text-xs text-muted-foreground` headers so new section types land somewhere meaningful. Shapes rejected on the way here: a permanent collapsible group under the tree (ate ~200px of a 256px sidebar), a compact icon strip (no room to grow, icon-only guessing), a labeled dropdown (a select implies picking an attribute, when the action is going somewhere and coming back), and putting the switcher in the same ghost icon row as the tab actions (three meanings in one shape).
- **A trigger that opens a menu takes no tooltip** — the menu names its own items, and the two layers collide on screen. Corollary: don't split one concept into a `+` plus a caret; either the button acts or it opens a menu.
- **Table toolbar** (`-tabs/table/-components/toolbar/toolbar.tsx`): filter field flex-1 left, delete-on-selection, columns/sort, `⋯` overflow. `items-end` so buttons stay anchored while the field grows upward. The stats pill (`TableStats`) is `shrink-0 whitespace-nowrap` beside that flex-1 field, renders row totals with `NumberFlow` in compact notation, and puts the exact locale-grouped numbers in its tooltip — abbreviate in the pill, be precise in the tooltip, and never let a counter's width drive the layout of the control next to it.
- **Empty states**: centered `rounded-2xl bg-muted/60` icon, `text-sm font-medium` title, `text-xs muted` hint, gentle fade/scale-in.
- **Shortcuts**: only via `packages/ui/src/components/custom/shortcuts.tsx` (`KbdCtrlLetter` etc., pass `userAgent`). Never hand-roll ⌘/Ctrl. Only advertise shortcuts that fire — gate Electron-only ones (⌘R) on `window.electron`.
- **Tooltips**: never nest triggers; `TooltipContent` is `inline-flex` — wrap multi-line content in `flex flex-col gap-0.5`.
- **Toasts** (`sonner.tsx`): `unstyled: true` + Tailwind classNames — glass (`rounded-xl bg-background/80 p-3 shadow-lg ring-1 ring-foreground/4 backdrop-blur-xl`), filled Remix icons in semantic colors. Never sonner's default theme.
- **Copy**: kit `CopyButton` (copy→check morph); silent `copy(text)` when the morph is confirmation enough.
- **Interactive icons — app-wide rule**: hover surface (`ghost` icon Button + `hover:bg-foreground/5`), icon `muted → foreground`, `Tooltip` naming the action; latched state `bg-foreground/10 text-primary`. Toggles (pin/unpin) swap icon on button hover (`group/pin` + hidden/block pair). In cmdk rows, reveal via `group-data-selected/command-item:opacity-100` (keyboard too) and wrap the button in `CommandShortcut`. Reference: `ResourceRow` in `connections-list.tsx`. Upgrade bare icons whenever touching a file.
- **Count badges**: absolute `-top-1.5 -right-1.5 h-4 min-w-4 rounded-full bg-primary text-2xs`; Button needs `relative overflow-visible`.
- **Upsell/hero dialogs** (`apps/app/src/components/subscription-modal.tsx`): centered layout — glow icon chip (`size-14 rounded-2xl bg-primary/10 inset-ring inset-ring-primary/15`, filled Remix icon, behind it `absolute -inset-5 rounded-full bg-primary/20 blur-2xl`), `text-lg` title, one-line muted description, perks as a `rounded-xl bg-foreground/3 divide-y divide-foreground/5` list (primary icons, `text-sm` labels), footer buttons `sm:flex-1` full-split, `text-xs` centered footnote. Top wash `bg-linear-to-b from-primary/8 via-background via-40%`. Copy stays minimal — no paragraph selling.
- **Nav fires on mousedown, not click** — for instant (Linear-style) feel, route navigation activates on press. **Always import `Link` from `~/components/link.tsx`, never from `@tanstack/react-router`.** It's a `createLink` wrapper whose anchor fires a synthetic `.click()` on mousedown, then swallows the real follow-up click in the capture phase — telling the two apart by `e.detail` (synthetic `.click()` and keyboard Enter are `detail 0`; a real mouse click is `detail >= 1`). Guards preserve cmd/ctrl/shift/alt-click (open-in-new-tab) and skip `target=_blank`. **Menus are the exception** — base-ui `DropdownMenuItem render={<Link/>}` must pass `activateOn="click"` to keep native mouseup activation (macOS menu semantics). For imperative press-nav on plain buttons/tabs (not `<Link>`), spread `pressNavProps(fire)` from `~/lib/press-nav.ts` (`onMouseDown` on plain press + `onClick` keyboard fallback via `detail 0`); if the button has a nested click target (e.g. a tab's close ✕), give that child `onMouseDown={e => e.stopPropagation()}` so the press doesn't navigate first. Reference: `tab-bar.tsx` `Tab`. **Draggable elements keep press-nav too** — grabbing a tab to reorder it also focuses it, which is the intended behavior (Finder/Chrome do the same). A mouseup-with-drag-slop variant was tried and reverted: besides losing the instant press feel, navigating on the second mouseup of a double-click blurs the rename input the instant it mounts, so inline rename silently stopped working.
- **Dialog rails**: `SidebarLink`/`SidebarButton` from `~/components/sidebar-link.tsx` — `h-7 rounded-md text-sm`, solid `bg-primary` active. (Sidebar lists themselves use `SidebarMenuButton` from `navigator/primitives.tsx`.)
- **Unified filter field** (`-tabs/table/-components/toolbar/filter-search-bar.tsx`): input-styled container (`min-h-8 flex-wrap bg-input rounded-xl`, `has-[input:focus]` ring) with chips inline + bare `CommandPrimitive.Input`. Suggestion panel opens upward (`absolute bottom-full mb-2 bg-popover rounded-xl p-1`, kit `CommandList` in unstyled `CommandPrimitive`); `onMouseDown preventDefault` keeps focus. Stage machine column → operator → value; pending chip styled like committed chips minus eye/✕. Value stage adds "Suggested values" (enums via `column.availableValues`, booleans true/false) — pick applies immediately, or toggles into the comma list for `isArray`. Backspace on empty steps back / pops last chip; ⌘F focuses; Escape cancels stage then blurs. Chips are `h-5 bg-[color-mix(in_oklch,var(--input),var(--foreground)_4%)] shadow-2xs` (search icon gets `mr-1` so chips/text don't crowd it) — the foreground-mix over the field's own surface reads slightly darker in light and slightly lighter in dark (`bg-background` was rejected: darker than the field in dark mode).
- **Command palette** (`apps/app/src/routes/-components/actions-center.tsx` + kit `CommandDialog`): shell is `top-[16svh] translate-y-0` with `max-h-[min(35rem,calc(84svh-2rem))] flex flex-col sm:max-w-xl` so it never overflows short viewports; surface is `bg-background` (from DialogContent), inner `Command` gets `bg-transparent p-0 min-h-0 flex-1`. Header is a borderless large input row (`border-b px-4`, search icon + bare `CommandPrimitive.Input` `h-12 text-base`), not the boxed kit `CommandInput`. List: `flex-1 max-h-none scroll-fade scroll-py-2 p-1` (kit default `max-h-72` must be overridden). Footer: `border-t px-4 py-2 text-2xs` kbd hints. Item icons rely on kit auto `size-4` — pass `text-muted-foreground` only.
- **Auth backdrop**: `DitherBackground` (kit `custom/dither-background.tsx`) wraps paper-design `Dithering` (`shape="warp"` default / `ripple` prop, `type="8x8"`, size 2, speed 0.3, 0 under reduced-motion). Literal hex palettes per `useResolvedTheme()` (WebGL can't read CSS vars), neutral grays near `bg-body` — blue rejected. Bottom quarter fades via CSS `mask-[linear-gradient(...)]` so the anchored quote stays readable. Both auth pages use it; app auth mirrors the web split layout (left panel logo + quote, right form).
- **Title-bar entity switchers** (`_protected/-components/protected-titlebar.tsx` + `workspace-switcher.tsx`): a `DropdownMenu` triggered by a ghost `Button size="sm"` with `gap-1.5 px-2` and a `max-w-*` cap, showing an optional glyph + `data-mask` truncated `font-medium` name + trailing `RiExpandUpDownLine` (`size-3 text-muted-foreground/70`). Segments joined by `RiArrowRightSLine` (`size-3.5 text-muted-foreground/40`) — order is `AppLogo → WorkspaceSwitcher → ⟩ → ConnectionsBreadcrumb → ⟩ → ResourcesDropdown`. Content is `align="start" max-h-[70vh] min-w-56 overflow-auto`; the active item gets a trailing `RiCheckLine` (`ml-auto size-4 text-muted-foreground`); a `DropdownMenuSeparator` sits above the terminal create/add action (`RiAddLine`). Workspace glyph is a `size-4 rounded bg-muted text-2xs font-medium` box with the name's first initial (stand-in until real logos). Subscription-gated actions (Create workspace) always render enabled and route free users to `setIsSubscriptionDialogOpen(true)` instead of disabling — the upsell modal is the gate, not a greyed item.
- **Table body skeleton** (`-tabs/table/-components/table/table-skeleton.tsx`): kit `Skeleton` bars aligned to real column widths (falls back to 6 default columns), deterministic width variation via sin-hash pseudo-random (never `Math.random`): each column gets a base width (35–80%), each row jitters ±12% around it — mimics real data where a column has a characteristic value length, per-row `animationDelay` stagger (90ms) for a cascading pulse, rows fade toward the bottom via opacity ramp, no row borders.
