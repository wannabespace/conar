# Kit gotchas

- `CommandDialog` is only a Dialog shell — wrap contents in `<Command>` or cmdk crashes (`undefined (reading 'subscribe')`).
- `CommandItem` appends a hidden `ml-auto` check — a second `ml-auto` child splits space. Right-aligned meta goes in `CommandShortcut` (also hides the check). Name span: `min-w-0 flex-1 truncate`. Give items an explicit `value` when they can mount mid-search (textContent of a filtered-out item is unreadable → stuck hidden).
- `PopoverContent` defaults `flex flex-col gap-4 p-4 w-72` — menu-like popovers need `gap-0 p-1`, often `w-auto`.
- `DropdownMenuLabel` requires a `DropdownMenuGroup` parent (base-ui throws `MenuGroupContext is missing`).
- base-ui render prop: `<Trigger render={<Button/>}>children</Trigger>` — children land inside. Non-button trigger needs `nativeButton={false}` + `aria-label`. Same for `<Button render={<Link/>}>` — no auto-inference in the kit, set it at the call site.
- `InputGroup` addon sizes direct-child svgs only — nested icons need explicit `size-4`.
- Router `Link` concatenates `activeProps.className` (no tw-merge) — use `data-[status=active]:` variants in one className (`sidebar-link.tsx`).
- CSS transitions can't interpolate length↔percentage (`max-w-64 → max-w-full` snaps) — keep both endpoints in rem.
- Selects: macOS overlay mode (`alignItemWithTrigger`) + `min-w-(--anchor-width)`; never fix-width a trigger narrower than its longest option. Sizes: set `size` on `SelectTrigger` AND `SelectContent` (popup carries `data-size`; items follow via `in-data-[size=xs]:`).
- Hotkeys: always `e.preventDefault()` (⌘P opens print otherwise). `getOS(navigator.userAgent)` for ⌘ vs Ctrl labels.
- Scroll-edge fades must never cover the scrollbar: masks clip it, overlay siblings paint over it. Data table puts gradients INSIDE the scroller as sticky zero-height anchors (`table-fade*`, globals.css + `packages/table/src/table.tsx`) — descendants can't paint over their own scroller's scrollbar. Shadcn `scroll-fade` (mask) only with `no-scrollbar`.
- cmdk 1.1.1 filtering is broken for grouped palettes (groups never reorder by score; stale scrollTop when selection persists across keystrokes). The actions center bypasses it: `shouldFilter={false}` + own search — entries as `{value, keywords, node}`, scored with cmdk's `defaultFilter` (re-exported from kit command.tsx), grouped when idle, one flat score-sorted list while searching, scroll reset in the controlled input's `onValueChange`.
- Native context menu (`apps/desktop/src/main/lib/context-menu.ts`): Electron `Menu.popup`'s item-`click` can fire AFTER the close `callback` (platform-dependent order), so a naive close→resolve-null races the click. Fix: resolve on `click` immediately; the close `callback` schedules `settle(null)` after a 150ms delay so a late click wins; a `settled` flag keeps it single-resolution. Also: `packages/ui` must stay electron-agnostic — the platform branch lives in `AppContextMenu` in `apps/app`, never in the kit. Native has no icons, no red destructive styling, and group labels map to `type: 'header'` (macOS 14+) / disabled item elsewhere; accelerators are display-only (`registerAccelerator: false`).
- Base Button has `active:not-aria-[haspopup]:translate-y-px` (press dip). It **replaces** any transform you set for layout — an absolutely-centered icon button (`-translate-y-1/2`) jumps from centered to +1px on press (reads as lag). Don't center buttons with `translate` + `absolute`; put them in-flow (flex sibling, `items-center`) so the press dip stays a clean 1px. If you must, re-assert the centering on active (`active:-translate-y-1/2!`).
- `motion.create(X)` belongs in its own `x.motion.tsx`, never in `x.utils.ts`. `x.tsx` imports `xVariants` from `x.utils`, so a `motion.create` there imports `x.tsx` back — a cycle whose top-level `motion.create(X)` runs while `X` is still in TDZ: `Cannot access 'Button' before initialization`. `.utils.ts` stays value-free (cva variants only); `.motion.tsx` is a leaf.
- An `absolute`-positioned wrapper defaults to `display: block`, so an inline-level child (`Spinner`'s `<output class="inline-flex">`, any bare svg) sits on the line box's text baseline — the descender gap below it pushes the glyph visually ~2-3px above the box center, even with `top-1/2 -translate-y-1/2`. Symptom: swap-in loader rides higher than the label it replaces. Fix: give the absolute wrapper `flex items-center justify-center` (height then collapses to the icon, no line box). Applied in `packages/ui/src/components/custom/loading-content.tsx`.
- base-ui `Menu.Item` closes the menu on click by default. For in-menu setting toggles that should stay open (theme picker in `user-button.tsx`), pass `closeOnClick={false}` — the dot/check indicator is the feedback, so the menu must survive the click.

- **Monaco view zones render in a detached React root** — `render`/`renderWithRoot` from `@tamery/ui/lib/render` mount into a bare DOM node handed to `editor.changeViewZones`, outside the app tree. Nothing crosses that boundary: no React context, no router context, no QueryClientProvider. Zone components (`RunnerEditorQueryZone`, `RunnerEditorAIZone`) must take everything as props (ids, connection, handlers), read state through module-level memoized stores (`runnerPageStore({resourceId, tabId})`, `getEditorQueriesComputed(...)`), and pass `queryClient` explicitly to `useQuery`/`useMutation`/`useIsFetching`. Swapping such a prop for a context hook typechecks fine and then throws `... is not provided` at runtime the moment a zone mounts.

- **`Reorder.Group` values must be stable primitives, not objects** — `Reorder.Group` keeps an `itemLayouts` Map keyed by each item's `value` **by identity**, and prunes every key missing from the current `values` set on each render. Feed it objects that get recreated (e.g. rows re-parsed out of a `createWebStorageValue` store on every write) and each unrelated store write evicts and re-registers every item, re-measuring layout — the strip visibly twitches in width and position while nothing changed. Pass ids (`values={tabs.map(t => t.id)}`, `<Reorder.Item value={tab.id}>`) and map back in `onReorder`. Pair with `layout="position"` on the item so genuine label-width changes (preview italics, ordinals) snap instead of animating the box. Always set `axis` explicitly too — without it the group runs `detectAxis` on every `registerItem` and can `setState` mid-measure. Reference: `$resourceId/-components/tab-bar.tsx`.

- **Streamdown renders unstyled without `@source`.** Its Tailwind classes live in `node_modules/streamdown/dist/*.js`, so `globals.css` needs `@source "../../node_modules/streamdown/dist/*.js"` or every list, table and block comes out with no spacing — the failure looks like broken layout, not a missing dependency. Its registry chrome also styles against `bg-sidebar`, a token this theme deliberately does not define.
- **Overriding `components.pre` replaces Streamdown's code block entirely** (verified: no `code-block-header` in the output). Useful — that is how the kit `CodeBlock` takes over — but a *partial* override, where you render your own header and still let its block wrap the `pre`, produces two nested cards with a gap between them.

- **`animate-none` does not reliably cancel `animate-in`/`animate-out`.** Tailwind sorts utilities itself, so source order in the className is irrelevant: for the `data-open` variant it emits `animate-none` after `animate-in` (override works), but for `data-closed` it emits `animate-none` *before* `animate-out` — the exit animation wins and the popup keeps animating out. The Actions Center carried a dead `data-closed:animate-none` for exactly this reason. Don't fight it with more utilities (`!` or arbitrary variants); make the animation classes conditional instead. `DialogContent`/`DialogOverlay` take `animated` (default `true`) and simply omit the `animate-*` set when false — `CommandDialog` passes `animated={false}` so the palette shows and closes instantly. Base-ui unmounts as soon as there's no animation or transition to wait on, so removing the classes is what actually makes the close immediate. Verify any similar override by compiling the two candidates and reading which rule lands last, rather than assuming className order decides.
