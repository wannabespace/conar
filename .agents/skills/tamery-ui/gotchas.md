# Kit gotchas

- `CommandDialog` is only a Dialog shell — wrap contents in `<Command>` or cmdk crashes (`undefined (reading 'subscribe')`).
- `CommandItem` appends a hidden `ml-auto` check — a second `ml-auto` child splits space. Right-aligned meta goes in `CommandShortcut` (also hides the check). Name span: `min-w-0 flex-1 truncate`. Explicit `value` on items that can mount mid-search (textContent of a filtered-out item unreadable → stuck hidden).
- `PopoverContent` defaults `flex flex-col gap-4 p-4 w-72` — menu-like popovers need `gap-0 p-1`, often `w-auto`.
- `DropdownMenuLabel` requires a `DropdownMenuGroup` parent (base-ui throws `MenuGroupContext is missing`).
- base-ui render prop: `<Trigger render={<Button/>}>children</Trigger>` — children land inside. Non-button trigger needs `nativeButton={false}` + `aria-label`. Same for `<Button render={<Link/>}>` — no auto-inference in the kit, set at call site.
- `InputGroup` addon sizes direct-child svgs only — nested icons need explicit `size-4`.
- Router `Link` concatenates `activeProps.className` (no tw-merge) — use `data-[status=active]:` variants in one className (`sidebar-link.tsx`).
- CSS transitions can't interpolate length↔percentage (`max-w-64 → max-w-full` snaps) — keep both endpoints in rem.
- Selects: macOS overlay mode (`alignItemWithTrigger`) + `min-w-(--anchor-width)`; never fix-width a trigger narrower than its longest option. Sizes: `size` on `SelectTrigger` AND `SelectContent` (popup carries `data-size`; items follow via `in-data-[size=xs]:`).
- Hotkeys: always `e.preventDefault()` (⌘P opens print otherwise). `getOS(navigator.userAgent)` for ⌘ vs Ctrl labels.
- Scroll-edge fades must never cover the scrollbar: masks clip it, overlay siblings paint over it. Data table puts gradients INSIDE the scroller as sticky zero-height anchors (`table-fade*`, globals.css + `packages/table/src/table.tsx`) — descendants can't paint over their own scroller's scrollbar. Shadcn `scroll-fade` (mask) only with `no-scrollbar`.
- cmdk 1.1.1 filtering broken for grouped palettes (groups never reorder by score; stale scrollTop when selection persists across keystrokes). Actions center bypasses: `shouldFilter={false}` + own search — entries as `{value, keywords, node}`, scored with cmdk's `defaultFilter` (re-exported from kit command.tsx), grouped when idle, one flat score-sorted list while searching, scroll reset in the controlled input's `onValueChange`.
- Native context menu (`apps/desktop/src/main/lib/context-menu.ts`): Electron `Menu.popup`'s item-`click` can fire AFTER the close `callback` (platform-dependent) — naive close→resolve-null races the click. Fix: resolve on `click` immediately; close `callback` schedules `settle(null)` after 150ms so a late click wins; `settled` flag keeps single-resolution. `packages/ui` stays electron-agnostic — platform branch lives in `AppContextMenu` in `apps/app`, never the kit. Native: no icons, no red destructive styling; group labels → `type: 'header'` (macOS 14+) / disabled item elsewhere; accelerators display-only (`registerAccelerator: false`).
- Base Button has `active:not-aria-[haspopup]:translate-y-px` (press dip). It **replaces** any transform set for layout — an absolutely-centered icon button (`-translate-y-1/2`) jumps from centered to +1px on press. Don't center buttons with `translate` + `absolute`; put in-flow (flex sibling, `items-center`). If you must, re-assert centering on active (`active:-translate-y-1/2!`).
- `motion.create(X)` belongs in its own `x.motion.tsx`, never `x.utils.ts`. `x.tsx` imports `xVariants` from `x.utils`, so `motion.create` there imports `x.tsx` back — cycle whose top-level `motion.create(X)` runs while `X` is in TDZ: `Cannot access 'Button' before initialization`. `.utils.ts` stays value-free (cva variants only); `.motion.tsx` is a leaf.
- An `absolute` wrapper defaults `display: block`, so an inline-level child (`Spinner`'s `<output class="inline-flex">`, bare svg) sits on the line box's text baseline — descender gap pushes the glyph ~2-3px above box center even with `top-1/2 -translate-y-1/2`. Symptom: swap-in loader rides higher than the label. Fix: absolute wrapper gets `flex items-center justify-center`. Applied in `packages/ui/src/components/custom/loading-content.tsx`.
- base-ui `Menu.Item` closes the menu on click by default. In-menu toggles that should stay open (theme picker in `user-button.tsx`): `closeOnClick={false}` — the dot/check indicator is the feedback.

- **Monaco view zones render in a detached React root** — `render`/`renderWithRoot` from `@tamery/ui/lib/render` mount into a bare DOM node from `editor.changeViewZones`, outside the app tree. Nothing crosses: no React context, no router context, no QueryClientProvider. Zone components (`RunnerEditorQueryZone`, `RunnerEditorAIZone`) take everything as props (ids, connection, handlers), read state via module-level memoized stores (`runnerPageStore({resourceId, tabId})`, `getEditorQueriesComputed(...)`), pass `queryClient` explicitly to `useQuery`/`useMutation`/`useIsFetching`. Swapping a prop for a context hook typechecks, then throws `... is not provided` when a zone mounts.

- **`Reorder.Group` values must be stable primitives, not objects** — it keys `itemLayouts` Map by each item's `value` **identity** and prunes keys missing from `values` each render. Recreated objects (rows re-parsed from a `createWebStorageValue` store on every write) → every unrelated write evicts/re-registers all items, re-measuring layout — strip visibly twitches. Pass ids (`values={tabs.map(t => t.id)}`, `<Reorder.Item value={tab.id}>`), map back in `onReorder`. Pair with `layout="position"` so label-width changes (preview italics, ordinals) snap. Always set `axis` explicitly — without it the group runs `detectAxis` on every `registerItem` and can `setState` mid-measure. Ref: `$resourceId/-components/tab-bar.tsx`.

- **Streamdown renders unstyled without `@source`.** Its Tailwind classes live in `node_modules/streamdown/dist/*.js` — `globals.css` needs `@source "../../node_modules/streamdown/dist/*.js"` or lists/tables/blocks come out with no spacing (looks like broken layout, not a missing dep). Its registry chrome also styles against `bg-sidebar`, a token this theme deliberately lacks.
- **Overriding `components.pre` replaces Streamdown's code block entirely** (verified: no `code-block-header` in output). That's how kit `CodeBlock` takes over — but a *partial* override (own header + its block wrapping the `pre`) makes two nested cards with a gap.

- **`animate-none` does not reliably cancel `animate-in`/`animate-out`.** Tailwind sorts utilities itself — source order in className irrelevant: for `data-open` it emits `animate-none` after `animate-in` (override works), for `data-closed` before `animate-out` (exit animation wins). Don't fight with more utilities (`!`, arbitrary variants); make animation classes conditional. `DialogContent`/`DialogOverlay` take `animated` (default `true`) and omit the `animate-*` set when false — `CommandDialog` passes `animated={false}` so the palette shows/closes instantly. Base-ui unmounts as soon as there's no animation/transition to wait on. Verify similar overrides by compiling both candidates and reading which rule lands last.
- **A focusable control inside a `CommandItem` steals the keyboard's place.** cmdk keeps real focus on the input and only *marks* the highlighted row — a `<button>` in a row (remove ✕, inline toggle) is still tabbable/click-focusable; after activating you can end up with a focus ring on it while arrows stop working. Give such controls `tabIndex={-1}` + `onPointerDown` `preventDefault()` (keeps click, drops focus); every `onSelect` refocuses `CommandInput` via ref. Ref: `toolbar/actions/actions-order.tsx`.
