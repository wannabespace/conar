# Kit gotchas

- `CommandDialog` is only a Dialog shell — wrap contents in `<Command>` or cmdk crashes.
- `CommandItem` appends a hidden `ml-auto` check — right-aligned meta goes in `CommandShortcut` (also hides the check). Explicit `value` on items that can mount mid-search.
- `PopoverContent` defaults `flex flex-col gap-4 p-4 w-72` — menu-like popovers need `gap-0 p-1`, often `w-auto`.
- `DropdownMenuLabel` requires a `DropdownMenuGroup` parent (base-ui throws).
- base-ui render prop: `<Trigger render={<Button/>}>children</Trigger>` — children land inside. Non-button trigger needs `nativeButton={false}` + `aria-label`. Same for `<Button render={<a href/>}>`: jsx-a11y can't see the children through `render`, so the anchor needs its own `aria-label`.
- `InputGroup` addon sizes direct-child svgs only — nested icons need explicit `size-4`.
- `InputGroupButton` does not forward `size` to `Button` (it maps it to `inputGroupButtonVariants` instead), so `Button`'s per-size icon rules never apply and every size in that cva must set its own `[&_svg:not([class*='size-'])]:size-*`. A size that forgets it silently falls back to the base `size-4` — an icon too big for its box.
- Base Button has an `active:translate-y-px` press dip that **replaces** any layout transform — never center a button with `absolute` + `-translate-y-1/2` (it jumps on press); use `inset-y-0 my-auto` or in-flow flex.
- Router `Link` concatenates `activeProps.className` (no tw-merge) — use `data-[status=active]:` variants in one className.
- Selects: macOS overlay mode (`alignItemWithTrigger`) + `min-w-(--anchor-width)`; never fix-width a trigger narrower than its longest option; `size` goes on trigger AND content.
- Hotkeys: always `e.preventDefault()`; `getOS(navigator.userAgent)` for ⌘ vs Ctrl labels.
- Scroll-edge fades must never cover the scrollbar: masks clip it, overlay siblings paint over it — the data table puts gradients inside the scroller as sticky zero-height anchors (`table-fade*`); shadcn `scroll-fade` (mask) only with `no-scrollbar`.
- cmdk 1.1.1 group filtering is broken (groups never reorder by score) — the actions center bypasses with `shouldFilter={false}` + its own scoring via cmdk's `defaultFilter`.
- Electron `Menu.popup`'s item-`click` can fire AFTER the close callback — resolve on click immediately, settle null on a 150ms delay. Platform branch lives in `AppContextMenu` in `apps/app`; `packages/ui` stays electron-agnostic.
- `motion.create(X)` belongs in its own `x.motion.tsx`, never `x.utils.ts` — creates an import cycle that throws a TDZ error. `.utils.ts` stays value-free.
- base-ui `Menu.Item` closes the menu on click — in-menu toggles need `closeOnClick={false}`.
- **Monaco SQL takes the dialect id from `sqlDialects` (`entities/connection/utils/monaco.ts`), never `"sql"`** — only the `pgsql`/`mysql` contributions are registered (tokenizer, completions), so a `sql` model gets Monaco's stock grammar and no language features. Themes are `github-light`/`github-dark` in `components/monaco.tsx`, hand-mapped from shiki's palettes so editor and `CodeBlock` read as one — keep the two in step when touching either.
- **Monaco view zones render in a detached React root** — no context of any kind crosses (router, query client, stores). Zone components take everything as props / module-level stores and pass `queryClient` explicitly; swapping a prop for a context hook typechecks, then throws at mount.
- **`Reorder.Group` values must be stable primitives** — it keys layout by `value` identity, so recreated objects re-measure everything and the strip twitches. Pass ids; set `axis` explicitly.
- Streamdown needs `@source "../../node_modules/streamdown/dist/*.js"` in globals or it renders unstyled; its `pre` renders no element (it only stamps `data-block` on the code child), so `ResponseCodeBlock` takes over through `components.code` — branch on `'data-block' in props` for block vs inline, and drop the `node` prop before spreading onto the inline `<code>`.
- `@streamdown/code`'s `highlight` schedules a full tokenization on every cache miss and dedupes only its callbacks, so each call is real work — `CodeBlock` calls it from the store's `subscribe` alone and serves `getSnapshot` from its own per-instance cache. Calling it from `getSnapshot` tokenizes the block three or four times per render, once per streamed chunk.
- Shiki dark theme needs the one `!important` rule in globals (`.dark [data-slot='code-block'] span[style*='--shiki-dark']`) — the light color ships inline, so dark mode otherwise renders github-light and identifiers go invisible.
- **A `Button` variant with no rest text colour renders blue as a link.** The global `a { text-primary }` rule ([SKILL.md](SKILL.md) rule 7) sits in `@layer base`, so any utility beats it — but only if one is there. `outline` and `ghost` set `hover:text-foreground` without a rest colour, so `<Button render={<Link/>}>` inherited the anchor rule and came out blue. `outline` now carries `text-foreground`; `ghost` deliberately does not, because its icon buttons inherit `text-muted-foreground` from the row they sit in — a ghost button rendered as a link needs the colour at its call site.
- **`FieldLabel` wrapping a `Field` is the registry's choice card** — that is what the `has-[>[data-slot=field]]:` rules on it are for, and it is how a whole row becomes one hit target without a click handler. Reach for it before building a row out of `Item`.
- **A vertical kit `Field` stretches its direct children** (`*:w-full` on the `vertical`/`responsive` orientations) so labels and controls line up; anything else placed in one — a button, a chip — needs `w-fit`, and `self-start` does not help because the width, not the alignment, is what was set.
- **Kit `Field` and `FieldGroup` carry their spacing as variants, not a base gap.** `Field` puts the gap on `orientation` (`vertical`/stacked `responsive` 6px, `horizontal` 12px) because one base gap cannot serve a label stacked over its control and a label sitting beside it — 12px stacked reads as two unrelated rows. `FieldGroup` takes `size` (`default` 24px, `sm` 16px for pane density). A call site dialing `gap-*` on either is the signal the variant is wrong, not the value.
- **A popup whose root mounts already-open never plays its entrance.** base-ui seeds `mounted` from `open`, so when both are true on the first render the `'starting'` status is skipped and `data-starting-style` is never applied — the panel appears instantly and only the exit animates. A `key` that remounts a component to reset its form state does exactly this, so the drawer/dialog root must sit **above** the keyed component: the page owns `open`/`onOpenChange` on the shell and the keyed body renders the header, sections and footer into it. A body inside the portal also unmounts on close, which is what keeps its `useHotkeys` from firing against a closed panel.
- **A bare `duration-*`/`ease-*` with no `transition-*` utility animates everything.** Both set the real CSS property, and `transition-property` initially resolves to `all`, so the element transitions width, height and colour on any change. On a popup sized from `--anchor-width` that shows up as the panel sliding open when its anchor grows (combobox chips wrapping to a second row), and it makes base-ui hold the popup mounted for the duration on close. Durations belong with the animation they time — kill both when the animation is cancelled.
- **`animate-none` does not reliably cancel `animate-in`/`animate-out`** (Tailwind's own utility ordering wins) — make animation classes conditional instead (`animated` prop on Dialog pieces; `CommandDialog` passes `animated={false}`).
- **`autoFocus` only covers the first render of a surface.** The HTML attribute focuses a candidate present when the document (or the popup) opens, so a row a click or Enter appends to a list mounts unfocused — a growing list focuses its new row itself, from a ref in an effect keyed on the flag that marked it new.
- A focusable control inside a `CommandItem` steals the keyboard's place — give it `tabIndex={-1}` + `preventDefault` on pointerdown; refocus `CommandInput` in `onSelect`.
- **A width-animated panel must have its content state ready on the opening frame** — mint the content's key synchronously in the interaction that opens it, not in a mount effect (content pops in mid-animation otherwise). Don't gate mounting on collection `isReady`; never block first paint on the network.
- Enter-to-submit fields must guard IME composition (`!event.nativeEvent.isComposing`) or CJK input submits half-composed.
- A `render={<Button/>}` wrapper that hard-codes surface classes makes the `variant` prop a lie — wrapper classes own position/animation/shape; the surface belongs to the variant.
- Desktop kills text selection app-wide (`.electron body` `select-none`, opt-back-in by element type only) — any component whose job is displaying readable prose needs `select-text` (kit `MessageContent` carries it). The `code`/`pre` opt-in excludes `button *` — code inside a click target (query-logger rows) would otherwise select a word on the second of two fast clicks. Repro in browser by adding the `electron` class manually.
- `content-visibility: auto` breaks a scroller's scroll math (skipped items measure as estimates) — use real virtualization instead.
- **`scrollAnchor` pins a turn to the top and reserves a spacer under it, released only when the answer grows tall enough to fill that viewport** — so the same chat open in two windows of different heights un-pins at different moments and the two scrolls drift apart. The anchor pass also fires on an equal-count child mutation and scrolls to the first unhandled anchor (the oldest message), and the first turn added to an empty scroller never registers as handled. The chat therefore anchors nothing and lets provider `autoScroll` hold the bottom; the pending spinner still renders inside the last item, never as its own item.
- A 1px line can't be centered in an even gutter with whole-pixel padding — center with layout (`flex justify-center` in a symmetric span), not padding.
- `@tamery/table` column renderers are render props, not component types — `header.tsx`/`body.tsx` *call* them (`column.header({…})`); rendering `<column.header/>` remounts the cell subtree every parent render and kills local cell state.
- **Streamdown ships its own block spacing** — `li` carries `py-1` and every heading `mt-6 mb-2`, so kit prose margins stack on top and chat reads twice as airy as authored. `Response`'s prose string must *replace* those (zero the `li` padding and space items on the list instead, don't add `my-*` on top); its lists are also `list-inside`, which wraps continuation lines back under the marker — override to `list-outside` with a margin. Check the dist defaults before adding a margin.
- Tooltip positioner is `pointer-events-none` (kit). Its entrance scales the popup up from the trigger, so an un-gated tooltip lands under the cursor mid-animation: the trigger sees `mouseleave`, drops its hover state, and gets it back only when the popup settles — reads as the hover flickering off and on.
- A ghost icon button next to a filled input reads shorter than it is: measured they match to the pixel (`h-7` group vs `size-7` button, tops aligned), but the field's `bg-input` + `ring` + `shadow-xs` give it a visible lip the transparent button lacks. Fix by matching surfaces (`variant="outline"` + the field's radius), not by growing the button.
- **A class or `data-*` change on a big container recalcs its entire subtree** — measured on the connection page: ~90ms for the resource layout (1750 nodes), ~45ms for the chat pane, ~20ms for the navigator, sub-millisecond on a button; inline `style` edits on the same elements take <1ms. Animation gates, folding flags and "settled" markers on the page-level panes must be inline styles (or refs), never attributes a rule selects on. Small leaf elements can keep their `data-*` state.
- **Never clear a React-managed inline style to `''` imperatively** — React only patches the keys whose prop value changed, so a `style.width` it set to `100%` and an effect later blanks stays blank forever (the element shrinks to its content after the first animation). Restore the value React rendered, or pin through a property React does not own (`minWidth`/`maxWidth`).
- **`motion-panels` sizes are plain pixel numbers**, so a pane resolves nothing against the group: the only measurements are the group's `offsetWidth`/`offsetHeight`, read once at fold start to pin the fill pane's content ([motion.md](motion.md)) and to bound a drag — `maxSize` is capped by the space the other sized panes leave, and is that whole space for a pane that omits it, so a pane can never push its sibling out of the group. A drag starts from the pane's own motion value, which is its rendered size. The package is outside the kit's Tailwind `@source` globs, so a className written in it produces no CSS — styling belongs in the kit wrapper. The separator is a `motion.div role="separator"` with a value (motion's pan gesture drives the drag; the separator only adds pointer capture so `:active` holds) (the a11y lint wants `hr`, which is void and cannot be focused or hold the line) — the disable is per line and deliberate. Its `aria-orientation` is its own (a vertical line in a horizontal group) and the kit wrapper styles off that — there is no `data-orientation`, which would have to carry the opposite word.
- **The resize separator must outrank panel content.** It is a sibling of the panes, so at an equal `z-index` the pane that comes later in the DOM wins and its sticky chrome (table header `z-10`, off-screen column buttons `z-20`) paints over the drag line — the hover/focus/active line looks cut off exactly where a sticky header sits. The kit separator sits at `z-30`, above every in-pane sticky layer and below floating popups.
- **Only the outermost resizable group clips.** A sized pane keeps its pixel size (`flex-shrink: 0`), so a window narrower than the panes add up to would spill them into scrollable document overflow — the root group takes `overflow: clip`, no scrollable overflow, unlike `hidden`. A nested group must stay `visible`: it sits flush against the card it holds, so clipping there cuts anything the card paints at its own edge, and the root's clip already keeps the overflow off the document. `overflow-clip-margin` looks like the fix and is not — the margin becomes scrollable overflow again (measured: a 32px margin grew the document by exactly 32px). `Group` finds the root by reading its own context before providing it.
- **Kit `Item` carries a 1px transparent border**, so a full-bleed row built on it sits 1px inside its container and `absolute` children resolve against the padding box. Full-bleed rows need `border-0`.
- **base-ui `Tabs.Panel` keeps an exiting panel mounted until `transitionend`** — with `transition-property: all` at `0s` it never fires, so the old panel stays (`data-ending-style` + `inert`) stacked under the new one. Render only the active panel.
- **Base UI writes orientation as `data-orientation="vertical|horizontal"`, never a bare `data-vertical`/`data-horizontal`.** Tailwind compiles `data-vertical:` to `[data-vertical]`, a dead selector — kit components use the `data-[orientation=…]:` form; a vendored registry component must be rewritten before use. Kit vertical separators size with `h-full`, so a fixed-height instance passes `h-4!` (the variant-prefixed base class outranks a bare `h-4`).
- **seitu `createWebStorageValue.set` is synchronous per call** — `JSON.stringify` → `localStorage.setItem` → a synthetic `StorageEvent` that wakes every persisted value on the page. Never call it per frame — a per-frame value belongs in component state and persists through a `debounce`. **`useSubscription` defaults to `deepEqual`** — a selector that returns a fresh array or carries payloads (query results) deep-compares all of it on every store change; pass `isEqual: Object.is` and let the store hand out a new reference when it changes.
- **base-ui `Combobox` `items` must be a referentially stable array.** A layout effect pushes `items` into the combobox store on every identity change, so an inline `data.map(...)` at the call site re-filters the list, rewrites the list refs and commits a second render on every keystroke and every chip toggle. Derive the array where it can be memoized — a module-scope TanStack Query `select` (`resourceTableColumnIdsQueryOptions`) keeps the reference across renders — and give the wrapper a module-scope empty array as the default so the loading state is stable too.
- **A table skeleton must pin the same column widths the data will get.** In an auto-layout table that means either declaring widths on `TableHead` (the account tables) or giving the skeleton cells the real cells' width classes and sizing the bars in `ch`; a skeleton that stands in for the whole table rather than its rows is the worst case — the swap replaces bars with a five-column grid. A skeleton over explicit pixel columns (the data table's `TableBodySkeleton`, which reads `column.size`) is already stable and percentage bars are fine inside it.
- **A percentage-width skeleton bar reserves no width in an auto-layout table.** Percentages resolve against a column whose width is still being computed, so they contribute nothing intrinsic and the loading table sizes every column from its header text — then reflows the instant real values arrive. Skeleton bars in a table are sized in `ch`, and the skeleton cells take the same width classes as the real ones (`w-full` on the grow column, `w-px` on the rest); without them the loading table has no grow column at all and the swap is a full relayout, not a nudge.
- **`AnimatePresence` only tracks its own direct children.** Rows rendered by a wrapper component (`<SkeletonRows/>` returning an array of `motion.tr`) are one opaque child to presence, so their `exit` never runs and they **stay mounted forever** — the definitions table kept six skeleton rows above the real data. Either render the array inline with keys, or keep such rows outside the presence tree and swap them on the flag.
- **The kit choice-card (a `FieldLabel` wrapping a `Field`) hovers on its hairline, not its fill.** Its surface is `bg-input`, which is pure white in light theme sitting on a near-white pane — any hover tint mixes *downward*, drops the card below the pane and reads as a hole rather than a hover. It hovers by firming `ring-foreground/4` to `/12` (with `transition-shadow`, since a `ring` is a box-shadow and `transition-colors` never animates it).
- **`autoFocus` does not focus an input mounted by an interaction** (verified in the tab bar's inline rename: the input renders, `document.activeElement` stays `BODY`, so nothing is selected and the blur-to-commit never fires). Focus and select from a ref callback (`ref={(input) => { input?.focus(); input?.select() }}`) — imperative focus lands and holds.

- **Chrome's autofill paints the `input`, not the control around it.** A field whose surface belongs to an `InputGroup` (every `field.Input`, `field.PasswordInput`, every `EditableList` row) has a transparent square input sitting inside a rounded filled box, so an autofilled value drew a blue rectangle that broke out of the rounding and stopped short of the addon. The UA fill cannot be overridden with `background-color`; kit `Input` neutralises it with `autofill:shadow-[inset_0_0_0_1000px_var(--input)]` plus `autofill:[-webkit-text-fill-color:var(--foreground)]`, so an autofilled field looks like any other filled one. It has to be the `shadow-*` utility, never an arbitrary `[box-shadow:…]` — Tailwind composes rings into `box-shadow`, so setting the property outright erases the focus and invalid rings on exactly the fields most likely to be autofilled.

- **A dialog's submit button is outside its `<form>`.** `DialogFooter` is a sibling of the content, so a `type="submit"` button there is not in the form's tree and clicking it submits nothing at all — silently, since the button still renders enabled and pressed. Every dialog form needs an `id` and its footer button the matching `form="<id>"` (`Form` passes `id` straight through). Also: `required` on a field whose submit is disabled while that field is empty is dead — the native bubble can never fire, and if the disable is ever lifted the bubble preempts the house error UI, which is the reason `Form` sets `noValidate`.
