# Kit gotchas

- `CommandDialog` is only a Dialog shell — wrap contents in `<Command>` or cmdk crashes (`undefined (reading 'subscribe')`).
- `CommandItem` appends a hidden `ml-auto` check — a second `ml-auto` child splits space. Right-aligned meta goes in `CommandShortcut` (also hides the check). Name span: `min-w-0 flex-1 truncate`. Explicit `value` on items that can mount mid-search (textContent of a filtered-out item unreadable → stuck hidden).
- `PopoverContent` defaults `flex flex-col gap-4 p-4 w-72` — menu-like popovers need `gap-0 p-1`, often `w-auto`.
- `DropdownMenuLabel` requires a `DropdownMenuGroup` parent (base-ui throws `MenuGroupContext is missing`).
- base-ui render prop: `<Trigger render={<Button/>}>children</Trigger>` — children land inside. Non-button trigger needs `nativeButton={false}` + `aria-label`. Same for `<Button render={<Link/>}>` — no auto-inference in the kit, set at call site.
- `InputGroup` addon sizes direct-child svgs only — nested icons need explicit `size-4`.
- Never center a kit `Button` with `top-1/2 -translate-y-1/2`: the base has `active:not-aria-[haspopup]:translate-y-px` press-nudge, and the active `translate-y` replaces the centering one — button jumps half its height down on press (bit the sort-popover ✕, password eye, runner clear-search). Center absolutes with `inset-y-0 my-auto` instead. Popup triggers (`aria-haspopup`) are exempt from the nudge but use the same margin centering anyway.
- Router `Link` concatenates `activeProps.className` (no tw-merge) — use `data-[status=active]:` variants in one className (`sidebar-link.tsx`).
- CSS transitions can't interpolate length↔percentage (`max-w-64 → max-w-full` snaps) — keep both endpoints in rem.
- Selects: macOS overlay mode (`alignItemWithTrigger`) + `min-w-(--anchor-width)`; never fix-width a trigger narrower than its longest option. Sizes: `size` on `SelectTrigger` AND `SelectContent` (popup carries `data-size`; items follow via `in-data-[size=xs]:`).
- Hotkeys: always `e.preventDefault()` (⌘P opens print otherwise). `getOS(navigator.userAgent)` for ⌘ vs Ctrl labels.
- Scroll-edge fades must never cover the scrollbar: masks clip it, overlay siblings paint over it. Data table puts gradients INSIDE the scroller as sticky zero-height anchors (`table-fade*`, globals.css + `packages/table/src/table.tsx`) — descendants can't paint over their own scroller's scrollbar. Shadcn `scroll-fade` (mask) only with `no-scrollbar`.
- cmdk 1.1.1 filtering broken for grouped palettes (groups never reorder by score; stale scrollTop when selection persists across keystrokes). Actions center bypasses: `shouldFilter={false}` + own search — entries as `{value, keywords, node}`, scored with cmdk's `defaultFilter` (re-exported from kit command.tsx), grouped when idle, one flat score-sorted list while searching, scroll reset in the controlled input's `onValueChange`.
- Native context menu (`apps/desktop/src/main/lib/context-menu.ts`): Electron `Menu.popup`'s item-`click` can fire AFTER the close `callback` (platform-dependent) — naive close→resolve-null races the click. Fix: resolve on `click` immediately; close `callback` schedules `settle(null)` after 150ms so a late click wins; `settled` flag keeps single-resolution. `packages/ui` stays electron-agnostic — platform branch lives in `AppContextMenu` in `apps/app`, never the kit. Native: no icons, no red destructive styling; group labels → `type: 'header'` (macOS 14+) / disabled item elsewhere; accelerators display-only (`registerAccelerator: false`).
- Base Button has `active:not-aria-[haspopup]:translate-y-px` (press dip). It **replaces** any transform set for layout — an absolutely-centered icon button (`-translate-y-1/2`) jumps from centered to +1px on press. Don't center buttons with `translate` + `absolute`; put in-flow (flex sibling, `items-center`). If you must, re-assert centering on active (`active:-translate-y-1/2!`).
- `motion.create(X)` belongs in its own `x.motion.tsx`, never `x.utils.ts`. `x.tsx` imports `xVariants` from `x.utils`, so `motion.create` there imports `x.tsx` back — cycle whose top-level `motion.create(X)` runs while `X` is in TDZ: `Cannot access 'Button' before initialization`. `.utils.ts` stays value-free (cva variants only); `.motion.tsx` is a leaf.
- An `absolute` wrapper defaults `display: block`, so an inline-level child (`Spinner`'s `<output class="inline-flex">`, bare svg) sits on the line box's text baseline — descender gap pushes the glyph ~2-3px above box center even with `top-1/2 -translate-y-1/2`. Symptom: swap-in loader rides higher than the label. Fix: absolute wrapper gets `flex items-center justify-center`. Applied in `packages/ui/src/components/custom/loading-content.tsx`.
- base-ui `Menu.Item` closes the menu on click by default. In-menu toggles that should stay open (theme picker in `user-button.tsx`): `closeOnClick={false}` — the dot/check indicator is the feedback.

- **Monaco view zones render in a detached React root** — `render`/`renderWithRoot` from `@tamery/ui/lib/render` mount into a bare DOM node from `editor.changeViewZones`, outside the app tree. Nothing crosses: no React context, no router context, no QueryClientProvider. Zone components (`RunnerEditorQueryZone`, `RunnerEditorAIZone`) take everything as props (ids, connection, handlers), read state via module-level memoized stores (`runnerPageStore({resourceId, tabId})`, `getEditorQueriesComputed(...)`), pass `queryClient` explicitly to `useQuery`/`useMutation`/`useIsFetching`. Swapping a prop for a context hook typechecks, then throws `... is not provided` when a zone mounts.

- **`Reorder.Group` values must be stable primitives, not objects** — it keys `itemLayouts` Map by each item's `value` **identity** and prunes keys missing from `values` each render. Recreated objects (rows re-parsed from a `createWebStorageValue` store on every write) → every unrelated write evicts/re-registers all items, re-measuring layout — strip visibly twitches. Pass ids (`values={tabs.map(t => t.id)}`, `<Reorder.Item value={tab.id}>`), map back in `onReorder`. Pair with `layout="position"` so label-width changes (preview italics, ordinals) snap. Always set `axis` explicitly — without it the group runs `detectAxis` on every `registerItem` and can `setState` mid-measure. Ref: `$resourceId/-components/tab-bar.tsx`.

- **Streamdown renders unstyled without `@source`.** Its Tailwind classes live in `node_modules/streamdown/dist/*.js` — `globals.css` needs `@source "../../node_modules/streamdown/dist/*.js"` or lists/tables/blocks come out with no spacing (looks like broken layout, not a missing dep). Its registry chrome also styles against `bg-sidebar`, a token this theme deliberately lacks.
- **Overriding `components.pre` replaces Streamdown's code block entirely** (verified: no `code-block-header` in output). That's how kit `CodeBlock` takes over — but a *partial* override (own header + its block wrapping the `pre`) makes two nested cards with a gap.

- **`animate-none` does not reliably cancel `animate-in`/`animate-out`.** Tailwind sorts utilities itself — source order in className irrelevant: for `data-open` it emits `animate-none` after `animate-in` (override works), for `data-closed` before `animate-out` (exit animation wins). Don't fight with more utilities (`!`, arbitrary variants); make animation classes conditional. `DialogContent`/`DialogOverlay` take `animated` (default `true`) and omit the `animate-*` set when false — `CommandDialog` passes `animated={false}` so the palette shows/closes instantly. Base-ui unmounts as soon as there's no animation/transition to wait on. Verify similar overrides by compiling both candidates and reading which rule lands last.
- **A focusable control inside a `CommandItem` steals the keyboard's place.** cmdk keeps real focus on the input and only *marks* the highlighted row — a `<button>` in a row (remove ✕, inline toggle) is still tabbable/click-focusable; after activating you can end up with a focus ring on it while arrows stop working. Give such controls `tabIndex={-1}` + `onPointerDown` `preventDefault()` (keeps click, drops focus); every `onSelect` refocuses `CommandInput` via ref. Ref: `toolbar/actions/actions-order.tsx`.

- **Shiki's dark theme needs a rule that does not ship with the kit.** `@streamdown/code` emits both themes on every token: the light color as an inline `style="color: …"` and the dark one as `--shiki-dark`. Nothing consumes that variable by default, so in dark mode a `CodeBlock` renders **github-light** colors — keywords survive as red/blue, but plain identifiers land on `#24292e` and are invisible on the dark surface (the code looks half-deleted, not mis-colored, so it reads as a streaming bug). The fix is the one `!important` rule in `globals.css`'s `@layer base`: `.dark [data-slot='code-block'] span[style*='--shiki-dark'] { color: var(--shiki-dark) !important }` — inline styles can only be beaten by `!important`, and the attribute selector keeps it off the line wrappers that carry no token color. Found the day the first `Response` consumer shipped: `CodeBlock` is reachable only through `Response`, which had no caller between the v1 chat UI's removal and the v2 chat panel, so the gap sat dormant.

- **A width-animated panel must have its content state ready on the opening frame.** Minting the content's key in a mount `useEffect` (e.g. `chatId` when the chat panel opens) means the first painted frame has the panel expanding around an empty box — the effect fires after paint, so content pops in mid-animation. Mint the state synchronously in the interaction that opens the panel (the toggle's `store.set` computes `chatId: state.chatId ?? v7()`), and keep the effect only as a fallback for persisted `opened: true` with a null id. Same family: don't gate the chat session on collection `isReady` (owner decision — an `isReady` spinner gate was shipped and reverted); mount immediately, and the collection-adoption effect in `ChatSession` repaints the transcript when the local store delivers (`whenSynced()` stays out of the render path either way — never block first paint on the network). Ref: `chat-panel.tsx` + `ChatButton` in `protected-titlebar.tsx`.

- **Enter-to-submit fields must guard IME composition.** During CJK/Japanese composition the confirm key fires `keydown` with `key === 'Enter'` too — without a `!event.nativeEvent.isComposing` check the field submits half-composed text. Any input/textarea where Enter sends needs the guard. Ref: `chat/chat-input.tsx`.

- **A `render={<Button/>}` wrapper that hard-codes surface classes makes the `variant` prop a lie.** The wrapper's `className` wins over the rendered Button's variant classes, so `bg-*`/`hover:bg-*`/`border-*` written beside a `variant` prop silently override it — the component advertises `variant` while every value paints identically, and the two systems drift (kit `MessageScrollerButton` shipped `variant="secondary"` under a hard-coded `bg-background hover:bg-accent`, so it was neither secondary nor elevated: no shadow, and a grimy accent slab on hover). Wrapper classes own **position, animation, and shape**; the surface belongs to the variant. Same reason the fix is choosing the right variant, not writing a fourth `color-mix` hover at the call site.

- **Desktop kills text selection app-wide; readable content must opt back in.** `globals.css` gives `.electron body` `select-none` (native macOS chrome doesn't select) and opts back in **by element type only** — `input, textarea, select, code, pre, [contenteditable]`. Prose rendered as `div`/`p` is therefore unselectable in the desktop app while working fine in a browser, so this class of bug never shows up in browser testing (repro: add the `electron` class to `documentElement` in devtools). Any component whose job is displaying readable text needs `select-text` on itself — kit `MessageContent` carries it for chat turns (both the user `Bubble` and the assistant `Response` inherit from it). A fenced code block inside that prose was always selectable, which makes the bug read as "selection randomly works sometimes".

- **`content-visibility: auto` and a scroller's scroll math are incompatible.** A skipped item measures as its `contain-intrinsic-size` estimate, so any "scroll to the end" computes against placeholder heights: the chat opened ~13% down a 33k-tall transcript, and once the scroller re-pinned it landed in the placeholder void below the real content (visibly blank panel, `scrollHeight` 4.3k vs the real 44k). The kit's `MessageScrollerItem` carries neither utility for that reason — reach for real virtualization inside the scroller before reintroducing a CSS trick that lies about height.
- **`scrollAnchor` belongs to the *newest* user turn only, never every one.** The scroller's anchor pass also fires on an equal-count child mutation and then scrolls to the first anchor it has not handled yet — with every user turn anchored that is the oldest message, so the view slams to the top of the conversation. The chat transcript churns exactly that way: the pending `Spinner` item is swapped for the assistant message, removing one child and adding another with the count unchanged. Mark one anchor (`message.id === anchorId`, the last user message) so a re-anchor can only ever land on the current turn.

- **A 1px line can't be centered in an even gutter with whole-pixel padding.** The chat resize handle's `w-px` line in the `pl-2` (8px) gutter needs a 3.5px inset per side; `pl-1` gave 4/3 and the line visibly hugged the card edge on retina. Center with layout, not padding: the handle spans the gutter symmetrically (`-left-0.5 w-3`, 2px overhang each side) and `flex justify-center` puts the line on the exact half-pixel. Ref: `ResizeHandle` in `chat-panel.tsx`.

- **`@tamery/table` column renderers are render props, not component types — keep them that way.** `ColumnRenderer.header`/`.cell` are declared inline in the table's own render (`header: (props) => <TableHeaderCell …/>`), so their function identity changes on every parent render. Rendering them as `<column.header/>` made React see a new element *type* each time and remount the whole cell subtree — with the column resize handle that meant every mousemove (which writes `columnSizes` to the store) destroyed the handle's `isResizing` state, so its `data-resizing` styling vanished mid-drag and the resizer disappeared as soon as the drag overlay killed hover. `header.tsx`/`body.tsx` therefore *call* the renderer (`column.header({…})`); the returned element's type (`TableHeaderCell`) is stable, so cell state survives. Any local state in a header/body cell depends on this — never turn the call back into JSX element syntax.

- **The message scroller's `currentAnchorId` cannot name the last turns of a log.** It is set only for an anchor whose top has crossed the anchor line (`scrollMargin + scrollPreviousItemPeek`, 64px by default), and the final question can sit fully in view forever without ever scrolling that high — so a jump rail keyed on it alone leaves the last line unmarked while its message fills the screen. Take `useMessageScrollerScrollable()`'s `end`: while there is more below, the anchor is the reader's position; at the bottom, the newest **visible** question is. The rail marks position in two tones off the same hook, no hand-rolled geometry: `currentAnchorId` is the full-strength current line, every id in `visibleMessageIds` a mid-tone one (a viewport holding three turns lights three — a single mark says the reader is somewhere they are not). Test trap: `visibleMessageIds` comes from an `IntersectionObserver`, which never fires in a hidden tab — a background browser pane reports zero visible messages and every rail state reads as broken. Ref: `ChatJumpRail` in `chat-messages.tsx`.
