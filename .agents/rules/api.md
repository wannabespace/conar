# oRPC routers, secrets, and environment

## oRPC

- Copy the shape from a neighbouring router in `apps/api/orpc/routers/` and register it in `routers/index.ts`. `authMiddleware` puts `user`/`session` on context. Clients call through the generated `ORPCRouter` type, never a manual fetch.
- `create` procedures take exactly one item — never `type.or(schema, schema.array())`; collection handlers fan out with `Promise.all`.
- **Errors are declared, not constructed**: a procedure or middleware lists its codes in `.errors({ CODE: { message } })` and throws `errors.CODE()`, so the code and its message live in the contract the client is generated from. `new ORPCError(...)` only where no `errors` map exists — handler interceptors and helpers outside a procedure. Clients narrow with `isDefinedError`.
- `syncDiff`'s `updated` query is optional: an insert-only collection omits it rather than paying an `OR` branch per client row for a match that cannot happen.

## Chat

- `routers/ai/v1/chat.ts` (`ai.chat`) is **frozen** — shipped desktop builds parse its wire format; never change it, never import from it. It only gates old clients into a "update the app" error, since chat moved to `ai.stream`. `routers/ai/v2/` holds everything current. **Folders only**: barrels re-export flat so procedure paths stay `ai.chat` / `ai.stream`, never `ai.v1.*` / `ai.chat.*`. `ai.chat` is a procedure, so the namespace is taken — which is why the send endpoint is `ai.stream`.
- Stack: AI SDK (`ai` v7 + `@ai-sdk/react`) + `ai-retry` (cross-provider fallbacks) + `ai-resumable-stream` (Redis). Not `@tanstack/ai`.
- `ai.stream`: the wire carries only the new turn; the stored transcript is the model context, so a client can never send stale history. Titles generate server-side beside the first answer.
- `ai.attachStream` answers "what should be streaming into this chat right now" — the live stream when one exists (a pointer per chat, not per device), else a fresh stream when the transcript ends on a user turn that never concluded, decided once on the server. A turn that ended carries its own evidence (answered and failed turns persist an assistant message, a stopped one flags the user message), so only a crash mid-stream is eligible for the restart. Empty is nothing to stream, never an error. Deliberately not named `resume` — it can spend a model call.
- `ai.abortStream` publishes stop through Redis and flags the user turn stopped before it returns, so no tab re-attaches to a turn the user stopped; a client that merely leaves stops nothing.
- No output schemas on streaming procedures (the chunk union belongs to `ai`), and `ai.stream`'s `messages` schema stays loose — `validateUIMessages` is the real check and the loose shape keeps old clients valid.
- **Never wire the request signal into `streamText`** — streams are detached on purpose; only `stopChatStream` aborts. A reload is not a cancellation.
- **One starter**: `claimChatStream` sets the Redis pointer with **NX** and returns `null` to the loser, so both senders fall back to resuming the winner's stream and two tabs racing one turn watch one answer. `CONFLICT` is only for a pointer whose stream is already gone. The pointer is released on flush or a failed resume, and expires after an hour.
- **Ids are the idempotency**: the user turn's uuid v7 is minted client-side and is the row id (a re-ask lands on `onConflictDoNothing`); assistant ids are minted server-side. A re-ask therefore leaves the transcript ending on an assistant turn — that is what a regenerate looks like on the wire, so `ai.stream` deletes that answer before building the model context instead of asking the model to continue it. `keepAlive` holds the Redis stream open until the assistant row lands, so a reload mid-finish rejoins or finds the row, never neither.
- **`@tamery/ai` vs `apps/api` splits by dependency, not topic**: db/auth/oRPC stays in the app; models and stream lifecycle live in the package; persistence is handed in as `onFinish`. Provider fallbacks live only in the package's model list.
- **Usage**: capture is the package's, the row is the app's. `createAiUsage(onRecord)` hands persistence in the way `chatStream` takes `onFinish`, and returns `telemetry(scope)` — a per-call AI SDK telemetry integration, **not** a global registration and no ambient context. Pass it as the `telemetry` option of any model call and that call reports itself, with the `modelId` that actually answered, so an `ai-retry` fallback is reported as itself; a closure beats async context for a detached stream, and a call passing no telemetry records nothing (which is what keeps frozen chat v1 out). **Structured output goes through `generateText` with `Output.object`, never `generateObject`** — deprecated in this SDK and it skips the model-level hook, so nothing would be recorded. Prices come from LiteLLM's public sheet, fetched at first use and refreshed daily, keeping the last good value on a failed refresh. **Aborted streams record nothing and cannot** — the provider never sends a finish chunk, so no token counts exist.
- Errors surface generic; provider errors stay in server logs. Per-instance ownership is the upgrade path for a second api instance.
- **Client**: one `Chat` instance memoized outside React per chat id — identity never changes under a running send. `useChat` holds only the live exchange; settled turns come from the collections, merged by id, persisted rows winning. So a chat reopened from the collections has no live turns and `regenerate()` would throw — Retry re-sends the last user message under its persisted id, which the server reads as a re-ask. The SDK's mount-only `resume` option is not used: every tab attaches whenever the merged transcript ends on a user turn and the instance is idle, so a turn started in one tab streams into all of them. Re-entry is self-limiting. The transport maps an empty `attachStream` body to `null`, the SDK's "no active stream" signal — an empty stream would instead run the full request lifecycle (submitted flash, phantom finish).

## Secrets / environment

- Each app's `env.ts` validates env vars with ArkType. In development, service URLs default dynamically via portless (`monorepo.md`) — don't add them back to `.env`.
- Encryption secrets live in Infisical at `['users', userId]`, created in `databaseHooks.user.create.after`.
- Connection strings are encrypted per **workspace**, not per requester: `getWorkspaceSecret(workspaceId)` resolves the workspace owner's secret and every decrypt path passes the row's own `workspaceId`, so shared workspaces decrypt with one key once invites ship.
