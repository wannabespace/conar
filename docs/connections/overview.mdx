Connections live in one place so you can switch between databases and devices.

## Add a connection

<Steps>
  <Step title="Choose a database type">
    PostgreSQL, MySQL, MSSQL, or ClickHouse.
  </Step>
  <Step title="Enter a connection string">
    Paste your string and click **Test connection** to verify it before saving.
  </Step>
  <Step title="Name and configure">
    Set a name, a sync type (see below), and optionally a label and color. Click
    **Save**.
  </Step>
</Steps>

<Note>
  Tamery tests the connection before saving. If it fails, check the host, port,
  credentials, and database name. The test uses the available local proxy in the
  web app, including for localhost connections. Queries use the database
  selected in the Navigator.
</Note>

## Sync types

Sync type controls whether Tamery stores your password or connection string. Every option syncs the connection across your devices.

<Tabs>
  <Tab title="Cloud (with password)">
    The full connection string, including the password, is encrypted with your per-user key and stored in the cloud. Available on every device with no re-entry.

    Good for dev and staging.

  </Tab>
  <Tab title="Cloud (without password)">
    Only metadata (host, port, database, username) is stored; the password is never uploaded. You enter it on each device.

    Good for production or when policy forbids storing passwords externally.

  </Tab>
  <Tab title="Cloud (without connection string)">
    Only the name, label and color are stored; the connection string never leaves the device where you created it. Other devices list the connection but can't open it.

    Good when a database's address must not be stored externally.

  </Tab>
</Tabs>

## Organizing

- **Labels** — tag connections (e.g. `production`, `staging`) to group and filter them.
- **Colors** — color-code environments.
- **Pinning** — pin frequently used connections to the top.

Change a connection's name, label, color, or sync type anytime from its settings.

## Working offline

Most of Tamery works without an internet connection. Your connections, saved queries, and workspaces are stored on your device, so you can create and remove connections, save and rename queries, and — in the desktop app — query any database you can still reach.

Changes you make offline are saved on your device right away and sent to your account, in order, the next time Tamery is online. They survive restarting the app. If the server rejects a change — for example, because you removed the connection on another device — Tamery undoes it locally and shows the reason.

These need a connection: signing in, creating a workspace, and AI features. In the web app, running queries does too: `tamery proxy` checks your session with Tamery on every request, and remote databases go through Tamery's cloud proxy.
