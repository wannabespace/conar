## SQLite files

On desktop, drop a database file onto Tamery, paste its full path into **Add new**, or choose **SQLite** and pick the file with the folder button.

```text
sqlite:///Users/me/app.db
```

The file must already exist. A `~/` path is relative to the home folder on the computer opening it. Syncing the connection does not copy the file.

In the web app, run [`tamery proxy`](/cli/commands#tamery-proxy) on the computer that holds the file.

## Turso

Choose **Turso** and enter your database URL and auth token, or paste:

```text
TURSO_DATABASE_URL=libsql://your-database.turso.io
TURSO_AUTH_TOKEN=your-token
```

Self-hosted libSQL servers work too.

## Cloudflare D1

Choose **Cloudflare D1** and enter your account ID, database ID, and API token. Pasting the database's Cloudflare dashboard URL fills in the IDs.

The token needs **Account → D1 → Read** for reading, or **Edit** for making changes, scoped to your account.

Turso and D1 work in both desktop and web. Their tokens follow the same [sync rules](/connections/overview#choose-what-syncs) as passwords.

## What works

Browse and edit rows, run SQL, explore relationships, and manage indexes and triggers.

- Existing columns can be renamed, but their type and nullability cannot be changed in the form.
- Existing constraints are read-only.
- Turso and D1 cannot keep a transaction open between runs. Run the whole `BEGIN … COMMIT` block with **Run all** instead. D1 returns no rows from statements inside that block.
- **Stop** cannot interrupt a SQLite file query already running.
- D1 may round integers larger than JavaScript's safe integer range (`2^53 − 1`).
