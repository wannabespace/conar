Paste your provider's connection string into **Add new**, or fill in the fields:

```text
postgresql://user:password@localhost:5432/mydb
```

Both `postgresql://` and `postgres://` work. The default port is **5432**.

## Hosted databases

Copy the connection string from Supabase, Neon, Railway, or your provider. Replace password placeholders before saving.

Tamery may switch a pooled address to a session or direct address so transactions work correctly. Review any change shown in the form. For Supabase, use the **Session pooler** if your network cannot reach the direct server over IPv6.

## SSL

Keep the SSL settings supplied by your provider.

| Option | Behavior |
| --- | --- |
| `sslmode=disable` | Unencrypted connection. |
| `sslmode=require` | Encrypted, without verifying the certificate. |
| `sslmode=verify-full` | Encrypted, with certificate and hostname verification. |

```text
postgresql://user:password@db.example.com:5432/mydb?sslmode=verify-full
```

With no SSL option, Tamery tries an encrypted connection without certificate verification. It uses an unencrypted connection only if the server reports that SSL is unavailable.

## TimescaleDB

Choose **TimescaleDB** under **Engine**, or paste a connection string:

```text
timescale://user:password@localhost:5432/mydb
```

A Timescale Cloud connection string opens as TimescaleDB on its own, and so does a local `timescale/timescaledb` Docker container. Hypertables and continuous aggregates show up in the Navigator as tables and views. TimescaleDB's internal schemas, where chunks live, stay hidden.

For localhost in the web app, run the [local proxy](/cli/commands#tamery-proxy).
