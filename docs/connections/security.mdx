## Connection details

Connection strings are encrypted on your device. On desktop, the device key uses the system keychain where available.

You choose what reaches Tamery's cloud when you create a connection:

| Sync type | Stored in the cloud |
| --- | --- |
| **Full** | The complete connection string, encrypted. |
| **No password** | Connection details without the password, SSH secrets, or SSL key secrets. |
| **Metadata only** | Name, engine, label, and color. No connection string. |

Synced connection strings are encrypted with a workspace key. They are decrypted on Tamery's server when another device retrieves them, then sent over HTTPS. This is not end-to-end encryption.

## Where queries run

- **Desktop:** your computer connects to the database directly.
- **Web with `tamery proxy`:** the computer running the proxy connects to the database.
- **Web without a local proxy:** Tamery's cloud proxy connects to public database servers and handles the query and its results.

The cloud proxy cannot reach private addresses or open SQLite, DuckDB and certificate files on your computer. Use desktop or the local proxy for those. Connections whose secrets stay on your device also need desktop or the local proxy.

Encryption between Tamery and your database depends on the connection's SSL settings. Use your provider's recommended settings and certificate verification.

## SSH tunnels

SSH tunnels run on desktop only. Tamery checks the server's host key and asks before trusting an unknown one. A changed key is refused.

You can use your SSH agent, a key file, a pasted private key, or a password. `~/.ssh/config` is supported; `ProxyJump` and `ProxyCommand` are not.

## AI and your data

AI requests are processed on Tamery's servers using external model providers. Chat sends your messages; editor and filter features also send relevant schema context. Share only data you are allowed to send.

The built-in chat does not execute SQL. Coding agents connected through [MCP](/mcp/overview#connection-access) can read data and make changes according to the access you grant; their results become part of the agent's context.

### AI help with a failed test

**Explain with AI** sends connection diagnostics when you click it. Tamery removes connection identifiers and secrets from the error, and sends details such as the engine, port, SSL options, and whether the host is local or public.

## Agent access

MCP clients use a local access token. Keep it out of shared config files; regenerate it in **Settings → MCP** if it leaks.

For a database-enforced restriction, connect with a database user that has only the permissions you need. Tamery's read-only checks cannot prevent every side effect of a database function.
