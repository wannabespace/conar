Open a **Query** tab with **+** in the tab bar or **New query** in the Navigator. Completion suggests tables, columns, and SQL for your database; errors are underlined as you type.

## Run SQL

| Action                                  | macOS           | Windows / Linux  |
| --------------------------------------- | --------------- | ---------------- |
| Run the selection or current statement  | Cmd+Enter       | Ctrl+Enter       |
| Run all statements                      | Cmd+Shift+Enter | Ctrl+Shift+Enter |
| Save the selection or current statement | Cmd+S           | Ctrl+S           |
| Save the whole tab                      | Cmd+Shift+S     | Ctrl+Shift+S     |

You can also click **Run** beside a statement or **Run all** in the toolbar. **Stop** cancels a running query where the engine supports cancellation.

Results appear below the editor with row count, duration, search, and export. Multiple statements get separate results. Each result keeps up to **10,000 rows**; narrow the query if you need more specific data.

Statements that change or remove existing data ask for confirmation. `INSERT` and `CREATE` run immediately.

## Save and reuse

**Saved** holds queries for this connection. Pick one to open it in a new tab. Saving again creates another saved query.

**History** lists statements you ran on this device. To inspect queries made by the rest of the app, open **Query logger** at the bottom of the Navigator.

## Transactions

Run a `BEGIN … COMMIT` block with **Run all**, or run `BEGIN` on its own to work step by step. An open transaction shows **Commit** and **Rollback** in the toolbar.

Closing the tab or leaving the transaction idle for 15 minutes rolls it back. Open transactions use a separate database connection and can hold locks until you end them.

ClickHouse has no transactions. Turso and D1 require the whole block in one run. MySQL schema changes may commit immediately, even inside a transaction. On Oracle, `BEGIN` starts a PL/SQL block, so each statement commits as it runs; put statements in one `BEGIN … END;` block to run them together.

## Get AI help

With [Pro](/account/plans):

- **Edit with AI:** describe a change to the current statement with **Cmd/Ctrl+K**.
- **Fix with AI:** get a suggested correction after a query fails.
- **Completion:** press **Tab** to accept the grey suggestion.

Review AI edits before accepting and running them. The AI uses your schema and, for edits and fixes, the rest of the query tab as context.
