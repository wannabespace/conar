Click **Schema** at the top of the Navigator, then choose an object type. Pick a row to inspect its definition and available settings.

| Object | What you can inspect |
| --- | --- |
| **Enums** | PostgreSQL types and their allowed values. |
| **Indexes** | Indexed columns, uniqueness, and index type. |
| **Constraints** | Primary keys, foreign keys, unique keys, and checks. |
| **Functions** | Arguments, return type, and SQL body. |
| **Triggers** | Table, event, and trigger body or function. |
| **Policies** | Row access rules. |
| **Privileges** | MySQL grants and who holds them. |

Tamery shows the categories supported by your engine. For table relationships, open the [Visualizer](/features/schema-visualizer).

## Create, edit, or drop

Click **+ Add** to create an object. To edit one, open it, change the enabled fields, and save. Right-click a row to drop it; Tamery asks for confirmation.

Some changes require replacing the object. The save button names the action, such as **Rebuild index** or **Replace enum**. Check its warning before saving: replacement can affect dependent objects or permissions.

Read-only fields indicate changes Tamery cannot make safely through the form. You can use the [SQL editor](/features/sql-editor) for changes outside it.

## Row level security

On PostgreSQL, a policy takes effect only when row level security is enabled on its table. Right-click the table in the Navigator and choose **Enable RLS** or **Disable RLS**.

On SQL Server, use the policy's **Enabled** switch and configure its predicates in the inspector.
